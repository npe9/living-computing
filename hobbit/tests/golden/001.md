# 001 — One-parcel immediate and stack MOV, ADD, and the ADD3 accumulator at CSP+4

Every value below is read off the printed *ATT92010 Hobbit Microprocessor
Programmer's Reference Manual* (January 1993); the PDF page is the printed
page plus 8 for Chapter 1 and plus 58 for Chapter 3. Nothing here was
produced or checked by `bsv/`, `asm/` or `sem/`.

This trace fixes the one-parcel field layout — bit 15 = 0, opcode in bits
14:10, source in 9:5, destination in 4:0 (p. 1-21, Table 1-15 p. 1-22) —
and the integer accumulator rule: a trailing `3` stores the 32-bit result in
the word at `CSP+4` instead of in the destination operand (p. 1-28, p. 3-1),
where `CSP` is `SP` because PSW bit 9 = 1 (Table 1-8 sheet 2, p. 1-15) and
the accumulator word is `CSP+4` (Figure 1-4, p. 1-7).

The image is 4 word(s) = 16 byte(s); the program is 8 instruction(s), of which 8 retires in this run.

## Pre-state

Every run in this directory starts from the single pre-state fixed in
`README.md`:

| register | value | why |
|---|---|---|
| PC | `0x00000000` | reset start address, p. 1-36 |
| PSW | `0x00000200` | bit 9 = 1 makes SP the CSP (Table 1-8 sheet 2, p. 1-15); every other bit 0: kernel level, physical addressing, interrupts inhibited (IPL 0), tracing off |
| CONFIG | `0x00000000` | reset value: all caches disabled, demand prefetch, PC extension 0 (p. 1-36, p. 1-10) |
| SP | `0x00000100` | quad-aligned (p. 1-17) |
| MSP | `0x00000180` | quad-aligned, `SP <= MSP <= SP+256` (p. 1-13) |
| SHAD | `0x00000100` | p. 1-15: a direct write of PSW bit 9 requires SHAD to be updated to the new SP |
| ISP | `0x00000200` | quad-aligned (p. 1-12); never used, because PSW bit 9 selects SP |
| VB | `0x00000000` | never read inside a trace |
| memory | image at address 0, `0x00000000` elsewhere | `README.md`, "Memory" |

SP and MSP are quad-aligned stack pointers whose low 4 bits do not exist
(p. 1-17, p. 1-13), so no operand in these programs can be misaligned.

## Retirement lines

One line per retired instruction, in program order, in the fixed HRI format. `Lnn` numbers are used only by this document; the `.trace` file holds the same lines without them.

L01. `HRI pc=0000 insn=28a00000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000100 data=00000014 mask=0f trap=0`

Encoding: MOV `$20, R0` is the one-parcel monadic form: opcode `0x0A` in bits 14:10, the 5-bit `wai5` source in bits 9:5 and the 5-bit `stk5` destination in bits 4:0 (Table 1-15 p. 1-22; p. 3-32). `wai5` is unsigned and multiplied by 4 (Table 3-2 p. 3-4), so the field carries 20/4 = 5; 5-bit stack offsets are zero-extended and multiplied by four before being added to SP (p. 1-21, p. 1-22), so `stk5`=0 means `CSP+0`.

Transition: `dst = src` (p. 3-32) makes the word at 0x00000100 (SP+0) equal 0x00000014. Stack-offset addressing adds the offset to CSP (p. 1-27); SP and MSP do not move, because only CATCH, CRET, ENTER, POPN and RETURN maintain the stack cache and MSP (p. 1-6).

L02. `HRI pc=0002 insn=28410000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000104 data=00000008 mask=0f trap=0`

Encoding: Same opcode, `wai5`=2 (2*4 = 8) and `stk5`=1, which is zero-extended and multiplied by four (p. 1-22; Table 3-2 p. 3-4: `stk5` holds the offset divided by four) — 1*4 = 4 — so the destination is `CSP+4`. Parcel 0x2841 (p. 3-32).

Transition: `dst = src` (p. 3-32) makes *(0x00000100+4) = *(0x00000104) equal 0x00000008 (stack-offset addressing adds the offset to CSP, p. 1-27). `CSP+4` is the integer accumulator word (Figure 1-4, p. 1-7; p. 1-28 names it `R4`), so this ordinary MOV is also the trace's accumulator store; SP and MSP are unchanged (p. 1-6).

L03. `HRI pc=0004 insn=60220000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000108 data=00000008 mask=0f trap=0`

Encoding: `MOV.SS`, opcode `0x18`: source `stk5`=1 (1*4 = 4, so `CSP+4`), destination `stk5`=2 (2*4 = 8, so `CSP+8`), both word stack offsets (Table 1-15 p. 1-22; p. 1-22 scaling; p. 3-32). Parcel 0x6022.

Transition: Copies the accumulator word 0x00000104 (8, stored by L02) to 0x00000108; the single architectural write is the destination store, and the operand fetch is not a write. The accumulator is read here as plain memory at `CSP+4` rather than as a register, which is what `R4` means (p. 1-28), and no word this program reads is one it has not written earlier in the run.

L04. `HRI pc=0006 insn=58020000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000108 data=0000001c mask=0f trap=0`

Encoding: `ADD.SS`, opcode `0x16`: source `stk5`=0 (`CSP+0`), destination `stk5`=2 (`CSP+8`) (Table 1-15 p. 1-22; p. 1-22 scaling; p. 3-5). Parcel 0x5802.

Transition: `dst += src` (p. 3-5, Description) makes *(0x00000108) = 0x00000008 + 0x00000014 = 0x0000001c: the value added into the destination is the accumulator's former content, carried there by the ordinary move of L03. ADD also sets PSW.C on unsigned overflow and PSW.V on signed overflow (p. 3-5); neither is a field of the fixed line.

L05. `HRI pc=0008 insn=54a00000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000104 data=00000019 mask=0f trap=0`

Encoding: `ADD3.CS`, opcode `0x15`: 5-bit two's-complement `imm5`=5 in bits 9:5, `stk5`=0 (Table 1-15 p. 1-22; p. 3-5; `imm5` range -16..15, Table 3-2 p. 3-4). Parcel 0x54a0.

Transition: `Acc = dst + src` (p. 3-5) with dst the destination operand *(CSP+0) = 0x00000014 and src the immediate 5, so 0x00000014 + 5 = 0x00000019 is stored in the accumulator, the word at CSP+4 = 0x00000104 (p. 1-7). The destination operand itself is unchanged, which is what distinguishes ADD3 from ADD.

L06. `HRI pc=000a insn=5c400000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000104 data=00000030 mask=0f trap=0`

Encoding: `ADD3.SS`, opcode `0x17`: source `stk5`=2 (*(CSP+8) = 0x0000001c), destination `stk5`=0 (*(CSP+0) = 0x00000014). Parcel 0x5c40 (T1-15 p. 1-22; p. 3-5).

Transition: `Acc = dst + src` = 0x00000014 + 0x0000001c = 0x00000030, written to 0x00000104. The destination operand *(CSP+0) is left unchanged, so the accumulator word now holds a value that equals no other word the program has written; a model that stored the ADD3 result in the destination instead of at `CSP+4`, or that treated `R4` as a general register, differs on 0x00000104.

L07. `HRI pc=000c insn=2c020000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0`

Encoding: Niladic opcode `0x0B` in bits 14:10 with subcode `0x002` in bits 9:0 (Table 1-17 p. 1-22; parcel printed on p. 3-35). Parcel 0x2c02.

Transition: No operation (p. 3-35): no write, SP and MSP unchanged.

L08. `HRI pc=000e insn=2c020000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0`

Encoding: Second NOP, identical encoding (Table 1-17 p. 1-22; p. 3-35).

Transition: No operation. It exists only so that the image ends on a word boundary and the last instruction ends exactly at the image end, 0x00000010 (README, stop rule 2).

## Manual ambiguities and the choices they forced

- The source of `MOV.WS` is `wai5`, an *unsigned constant multiplied by 4* (Table 3-2 p. 3-4), so the field holds 5 for the value 20. `MOV $20` cannot use the `imm5` form (`MOV.CS`, opcode `0x1C`) because `imm5` is 5-bit two's complement, -16..15 (Table 3-2 p. 3-4). The manual does not say what an assembler does with a `wai5` operand that is not a multiple of 4; only multiples of 4 are used here.

- p. 3-5 prints `ADD: dst += dst` in the Operation block while the Description on the same page adds the source to the destination (and ADD3 is printed as `Acc = dst + src`). The trace uses `dst += src`; the printed `dst += dst` is a typo, recorded in `docs/isa_inventory.md` §7.3 item 6.

- The accumulator is not a register: it is the word at `CSP+4` (p. 1-7, Figure 1-4; p. 1-28). The fixed HRI line has no accumulator field, so an ADD3 is reported through the ordinary `we/addr/data` fields as a store to 0x00000104. The architectural fact this trace pins is the store to 0x00000104, so a model that computed the right value but reported no store, or stored to the destination operand instead, fails.

- `R4` and `R8` are stack offsets in words, not registers (p. 1-27 stack-offset mode; the manual reads `RETURN R4` as a word stack offset, p. 3-40, and p. 1-28 names the accumulator `R4` because it is the word at offset 4). `MOV R4, R8` therefore copies *(CSP+4) to *(CSP+8). The undefined `:L` suffix that p. 3-3's pipeline example prints is not used anywhere in these images (inventory §7.3 item 3).
