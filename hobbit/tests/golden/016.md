# Golden 016 — operands in memory: outside the stack cache's window

This trace fixes what an operand *outside* the stack cache is. p. 1-5
and p. 1-12 define the cache as the words `SP <= address < MSP`, at most
256 bytes; every other operand is a word of memory. Five cases, each one
instruction with one distinguishing value:

* an absolute-address word, stored and loaded back (L01, L02);
* a byte store into a memory word, which must merge with the three bytes
  already there (L04, L05; p. 1-4);
* a pointer whose target is in memory (L07; p. 1-27);
* a word that was in the cache and is in memory only because an ENTER
  flushed it (L08, L09; p. 3-19);
* a RETURN across a frame larger than the cache, whose return address is
  the caller's word above MSP (L12, L14; p. 3-40) — the case that sent
  the 1st Edition Plan 9 `cat` to address 0;
* one instruction with three operand words in memory — an absolute
  source, a pointer word and the word it names — right behind a store to
  the first of them (L21, L22).

The image is 28 words = 112 bytes; 23 instructions retire, and the
five-parcel instruction at `0x0040` is jumped over by the RETURN.

## How this file was derived

The state transitions, the SP/MSP values and every `cyc` were derived by
hand from the printed pages cited on each line, before either model was
run on the image. Two things differ from goldens 001–015 and are stated
rather than hidden:

* the parcels were assembled with `asm/hobbit_asm.py` and then checked
  field by field against Tables 1-15, 1-16, 1-18, 1-19 and 1-21; the
  `Encoding:` notes are that check;
* the first hand derivation of L12 gave `cyc=5` (one block for the 16
  bytes by which the frame exceeds 256). The independent model `sem/`
  printed 1, and the printed loop on p. 3-19 —
  `while ((MSP > SHAD) && (MSP - target > SCSIZE))` — decides it: with an
  empty cache MSP = SHAD and the loop does not run. The hand value was
  wrong, the trace was corrected to 1, and the same missing `MSP > SHAD`
  bound was then found and fixed in the core (`enterFlushBlocks`,
  `bsv/HobbitTypes.bsv`). The line is kept because that is what it
  catches.

## Pre-state

The fixed pre-state of `README.md`: PC `0x00000000`, PSW `0x00000200`
(bit 9: CSP = SP, p. 1-14), SP `0x00000100`, MSP `0x00000180`,
SHAD `0x00000100`, ISP `0x00000200`, VB `0`, CONFIG `0`, memory zero
except the image. The memory words used are `0x200` (L01–L07),
`0x2b0`–`0x3cf` (L08–L22) and `0x300`/`0x308` (L17–L22); none overlaps
the image or the pre-state window.

## Retirement lines

Cycle accounting: `MOV`, `ADD` and `NOP` are 1 and `RETURN` is 2 in Table 4-32
(p. 4-3); `ENTER` is 1 + (Q·E) (Table 4-36, p. 4-5) with E the blocks the
p. 3-19 loop moves and Q = 4 (a model choice, README). The p. 4-1
assumptions say "all stack offset accesses are captured in the stack
cache" and exclude absolute and indirect data operands; this trace
deliberately leaves them, and Table 4-38's operand-access delays are not
added to `cyc` (`sem/README.md`, choice 22; the core's memory fetch stalls
are not part of `cyc` either, `bsv/HobbitCore.bsv` "Memory operands").

L01. `HRI pc=0000 insn=86fc1234 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000200 data=00001234 mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: `86fc` = three parcels, opcode `0x06`, smode `F` (immediate), dmode `C` (`*$addr:W`, absolute word); source `0x1234`, destination address `0x0200` (Tables 1-18/1-21, pp. 1-24, 1-25).

Transition: The word at `0x200` receives `0x00001234`. `0x200` is outside the stack cache's window `[SP, MSP) = [0x100, 0x180)` (p. 1-5, p. 1-12), so this is a store to memory.

L02. `HRI pc=0006 insn=86cd0200 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000104 data=00001234 mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: `86cd`: smode `C` (absolute word), dmode `D` (`Roffset:W`); source address `0x0200`, destination offset `0x0004`.

Transition: `SP+4 = 0x104` receives the word at `0x200`, `0x00001234` — the value L01 stored one instruction earlier (`dst = src`, p. 3-32). A model that reads zero for an operand outside the cache prints `data=00000000` here.

L03. `HRI pc=000c insn=86fd00ab sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000108 data=000000ab mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: `86fd`: smode `F`, dmode `D`; source `0x00ab`, destination offset `0x0008`.

Transition: `SP+8 = 0x108` receives `0x000000ab`.

L04. `HRI pc=0012 insn=86d00008 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000200 data=00ab0000 mask=04 trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: `86d0`: smode `D`, dmode `0` (`*$addr:B`, absolute byte); source offset `0x0008`, destination address `0x0201` (Table 1-21 p. 1-25).

Transition: The byte at `0x201` receives the low byte of `SP+8`, `0xab`. Memory is big-endian: the byte at word address + 1 is bits 23:16 (p. 1-4), so the record's `data` is `0x00ab0000` with byte mark `04`, and the word at `0x200` becomes `0x00ab1234` — the other three bytes keep L01's value. A model that does not read the old word from memory leaves `0x00ab0000` there, which L05 would show.

L05. `HRI pc=0018 insn=86cd0200 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=0000010c data=00ab1234 mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: `86cd`: source address `0x0200`, destination offset `0x000c`.

Transition: `SP+12 = 0x10c` receives the whole word at `0x200` after L04's byte store: `0x00ab1234`.

L06. `HRI pc=001e insn=86fd0200 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000110 data=00000200 mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: `86fd`: source `0x0200`, destination offset `0x0010`.

Transition: `SP+16 = 0x110` receives `0x00000200`, the pointer L07 follows.

L07. `HRI pc=0024 insn=64850000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000114 data=00ab1234 mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3); the p. 4-1 assumptions exclude indirect operands, so no Table 4-38 delay is added, as in `015`.

Encoding: One parcel `6485`: the Table 1-15 (p. 1-22) `MOV *stk5, stk5` form, source `*R16` (`*Roffset:W`), destination `R20`; the five-bit fields are word offsets, scaled by 4 (p. 1-21).

Transition: p. 1-27: the word at `SP+16` (`0x200`) is fetched and used as the address of the data operand. `SP+20 = 0x114` receives the word at `0x200`, `0x00ab1234`: a pointer whose target is in memory, not in the stack cache.

L08. `HRI pc=0026 insn=80f90000 sp=00000100>000003c0 msp=00000180>000003c0 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=33`

Cycles: 33 — `ENTER` = 1 + (Q·E) (Table 4-36, p. 4-5). A non-stack-offset source flushes the cache while MSP > SHAD (p. 3-19 pseudocode): `0x180` down to `0x100` is 8 blocks; Q = 4 (model choice, README) ⇒ 1 + 4·8 = 33, exactly as `004` L04.

Encoding: `80f9 0000 03c0`: three-parcel monadic, smode `F`, subcode `0x9` = ENTER (Table 1-19 p. 1-24); operand `0x000003c0`.

Transition: `SHAD = MSP = SP = target = 0x3c0` (p. 3-19). The cache is now empty, and its eight blocks — `SP+4 = 0x104` among them — were written to memory by the flush loop.

L09. `HRI pc=002c insn=86cd0104 sp=000003c0>000003c0 msp=000003c0>000003c0 we=1 addr=000003c4 data=00001234 mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: `86cd`: source address `0x0104`, destination offset `0x0004`.

Transition: `0x104` held `0x00001234` in the stack cache (L02) and reached memory only through L08's flush; `SP+4 = 0x3c4` receives it. With `MSP = SP` the destination is outside the (empty) window too, so this is a memory-to-memory move. A model that reads memory before the flush has finished prints `data=00000000`.

L10. `HRI pc=0032 insn=60220000 sp=000003c0>000003c0 msp=000003c0>000003c0 we=1 addr=000003c8 data=00001234 mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: One parcel `6022`: Table 1-15 `MOV stk5, stk5`, source `R4`, destination `R8`.

Transition: `SP+8 = 0x3c8` receives `SP+4`, `0x00001234`, the word L09 stored one instruction earlier — a stack-offset operand that is not in the cache.

L11. `HRI pc=0034 insn=86fd004a sp=000003c0>000003c0 msp=000003c0>000003c0 we=1 addr=000003c0 data=0000004a mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: `86fd`: source `0x004a`, destination offset `0x0000`.

Transition: `SP+0 = 0x3c0` receives `0x0000004a`. This is the word a `CALL` would have written at CSP (p. 3-9): the return address L14 reads.

L12. `HRI pc=003a insn=0bbc0000 sp=000003c0>000002b0 msp=000003c0>000003b0 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `ENTER` = 1 + (Q·E) (Table 4-36, p. 4-5). The stack-offset loop is `while ((MSP > SHAD) && (MSP - target > SCSIZE))` (p. 3-19). `MSP - target` = `0x3c0 - 0x2b0` = 272 > 256, but MSP = SHAD = `0x3c0`: the cache is empty, the loop does not run, E = 0 and 1 + 0 = 1.

Encoding: One-parcel stack class `0bbc`: subcode 0 = ENTER, offset field `0xef`, one-filled and multiplied by 16 = −272 (Table 1-16 p. 1-22; p. 3-19; footnote a, p. 3-20).

Transition: `target = 0x3c0 - 272 = 0x2b0`. After the loop, `if (MSP > target + SCSIZE) MSP = target + SCSIZE` (p. 3-19) gives MSP = `0x3b0`; `SHAD = SP = 0x2b0`. The frame is 272 bytes, so the word at the old SP, `0x3c0`, now lies *above* MSP.

L13. `HRI pc=003c insn=70e10000 sp=000002b0>000002b0 msp=000003b0>000003b0 we=1 addr=000002b4 data=00000007 mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: One parcel `70e1`: Table 1-15 `MOV imm5, stk5`, immediate 7, destination `R4`.

Transition: `SP+4 = 0x2b4` receives `0x00000007`, inside the new window `[0x2b0, 0x3b0)`.

L14. `HRI pc=003e insn=08460000 sp=000002b0>000003c0 msp=000003b0>000003c0 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=2`

Cycles: 2 — `RETURN` is 2 in Table 4-32 (p. 4-3), and the table's note says a RETURN's indirection adds no delay.

Encoding: One-parcel stack class `0846`: subcode 2 = RETURN, offset field `0x11` × 16 = 272 (Table 1-16 p. 1-22; p. 3-40).

Transition: `PC = *(CSP + 272) = *(0x3c0) = 0x0000004a` (p. 3-40) — a word outside `[0x2b0, 0x3b0)`, read from memory. `SP += 272` = `0x3c0`; SP now exceeds MSP, so `MSP = SP = 0x3c0` (p. 3-40). The five-parcel `MOV $0xdead, R4` at `0x0040` is skipped and never retires. A model that reads zero for the caller's word returns to address 0 and runs the program again from L01.

L15. `HRI pc=004a insn=60230000 sp=000003c0>000003c0 msp=000003c0>000003c0 we=1 addr=000003cc data=00001234 mask=0f trap=0 cyc=1`

Transition: `SP+12 = 0x3cc` receives `SP+4 = 0x3c4`, still `0x00001234` from L09: neither L13's `7` (written at `0x2b4`) nor the skipped `0xdead`.

## Injections

Each bug was put into the core, `bsv/run_golden.sh 016` was run, the
difference from this trace recorded, and the exact patch reversed
(2026-11-19; the tree was byte-identical to the saved copy afterwards).
What is written here is what was observed on the 23-line trace, including
the injections it does **not** catch.  (The first two rows were first run
when the trace had 17 lines and recorded as "L07 only" for the second;
re-running on the final trace showed L22 as well, and the commit message
of 32350570 still carries the earlier wording.)

| injected bug | observed |
|---|---|
| an operand outside the cache reads zero (EU_S1 `memWord`'s miss returns `ok` with 0) — the behaviour before this change | L02, L05, L07, L09, L10 print `data=00000000`, and L14's RETURN goes to address 0: the program runs again from L01 without end |
| EU_S2 ignores the pointed-to word EU_S1 fetched from memory (`ptMem` treated as false) | L07 (`data=00000000` for `data=00ab1234`) and L22 (`data=00000003` for `data=00000013`), nothing else |
| `enterFlushBlocks` without the `MSP > SHAD` bound (the code before this change) | L12 only: `cyc=5` for `cyc=1` |
| operand fetch not gated on the box being idle (`sc.memIdle()` dropped) | **no difference** — ENTER's own issue interlock already keeps EU_S1 empty for the whole flush, so L09 does not reach the gate |
| a latched word not refreshed from EU_S3's write (the `snoop` function returns the latch unchanged) | **no difference** |
| the word arriving from memory not overridden by EU_S3's write in the same clock | **no difference** |

The last three are therefore argued from the structure, not tested: no
line of this trace holds a fetched word in a latch across an older
instruction's write, because in every case here the writer is already in
the bypass network when the reader first asks. L22 was added to try to
reach that path and does not. A test that does needs EU_S2's output slot
held while the writer waits in its input slot.
