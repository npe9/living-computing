# 004 — ENTER and POPN in the one-parcel and three-parcel forms, with the MSP rule

This trace fixes ENTER and POPN in both the one-parcel stack class
(Table 1-16 p. 1-22) and the three-parcel monadic form with a 32-bit operand
(Table 1-19 p. 1-24), and the two documented MSP updates: ENTER with a
non-stack-offset source empties the cache (p. 3-19), and POPN raises MSP
when the new CSP would exceed it (p. 3-38).

The image is 5 word(s) = 20 byte(s); the program is 6 instruction(s), of which 6 retires in this run.

## Pre-state

Every run in this directory starts from the single pre-state fixed in
`README.md`:

| register | value | why |
|---|---|---|
| PC | `0x00000000` | reset start address, p. 1-36 |
| PSW | `0x00000200` | bit 9 = 1 makes SP the CSP (Table 1-8 sheet 2, p. 1-15); every other bit 0: kernel level, physical addressing, interrupts inhibited (IPL 0), tracing off |
| CONFIG | `0x00000000` | reset value: all caches disabled, demand prefetch, PC extension 0 (p. 1-36, p. 1-10) |
| SP | `0x00000100` | quad-aligned (p. 1-17) |
| MSP | `0x00000180` | quad-aligned, `SP <= MSP <= SP+256` (p. 1-13) |
| SHAD | `0x00000100` | p. 1-15: a direct write of PSW bit 9 requires SHAD to be updated to the new SP |
| ISP | `0x00000200` | quad-aligned (p. 1-12); never used, because PSW bit 9 selects SP |
| VB | `0x00000000` | never read inside a trace |
| memory | image at address 0, `0x00000000` elsewhere | `README.md`, "Memory" |

SP and MSP are quad-aligned stack pointers whose low 4 bits do not exist
(p. 1-17, p. 1-13), so no operand in these programs can be misaligned.

## Retirement lines

One line per retired instruction, in program order, in the fixed HRI format. `Lnn` numbers are used only by this document; the `.trace` file holds the same lines without them.

Cycle accounting: `MOV` 1, `POPN` 2 and `NOP` 1 (Table 4-32, p. 4-3); `ENTER` is 1 + (Q·E) (Table 4-36, p. 4-5), with E the number of 16-byte blocks the pp. 3-19/3-20 flush loop moves. A distance that is not a multiple of 16 bytes is rounded up: the loop writes a whole block (`memory[MSP-16]` … `memory[MSP-4]`) and decrements by `MSP-=16` once per iteration, so a partial trailing block still costs one block. Both ENTERs here give exact multiples. Q=4 is a model choice, not a printed value (README, "Cycle model"). The p. 4-1 assumptions are adopted, so no Table 4-37/4-38/4-39/4-40 delay is added.

L01. `HRI pc=0000 insn=28800000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000100 data=00000010 mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Encoding: One-parcel `MOV.WS`, opcode `0x0A`, `wai5` = 4 (4*4 = 16), `stk5` = 0 (Table 1-15 p. 1-22; p. 3-32). Parcel 0x2880.

Transition: *(0x00000100) = 0x00000010. Only a diagnostic word: no other instruction of this program touches 0x00000100 (there is no CALL and no trap here), so it stays visible for the whole run even though SP leaves 0x00000100 twice.

L02. `HRI pc=0002 insn=0bf80000 sp=00000100>000000e0 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `ENTER` = 1 + (Q·E) (Table 4-36, p. 4-5). E = 0: MSP − target = 0x180 − 0x0e0 = 0xa0 = 160 ≤ SCSIZE 256, so the p. 3-19 stack-offset branch's flush loop does not run and no 16-byte block is moved, so Q does not enter numerically (Q = 4 is a model choice, README). 1 + 0 = 1.

Encoding: One-parcel stack class, subcode 0 = ENTER, offset field 0xFE, one-filled and multiplied by 16 (Table 1-16 p. 1-22; p. 3-19; footnote a, p. 3-20) = -32. Parcel 0x0bf8.

Transition: Stack-offset source with CSP = SP: MSP - target = 0x180 - 0x0e0 = 0xa0 < SCSIZE, so no flush (p. 3-19); SP = 0x000000e0, SHAD = SP, MSP unchanged at 0x00000180 (p. 3-20). No architectural store.

L03. `HRI pc=0004 insn=080b0000 sp=000000e0>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=2`

Cycles: 2 — `POPN` min=max=2 (Table 4-32, p. 4-3).

Encoding: One-parcel stack class, subcode 3 = POPN, offset field 0x02, zero-extended and multiplied by 16 (Table 1-16 p. 1-22; footnote a, p. 3-38) = 32. Parcel 0x080b.

Transition: `SHAD = CSP = CSP + src` = 0x000000e0 + 0x20 = 0x00000100 (p. 3-38). CSP = SP = 0x00000100 is not greater than MSP 0x00000180, so MSP stays 0x00000180. No store.

L04. `HRI pc=0006 insn=80f90000 sp=00000100>000000c0 msp=00000180>000000c0 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=33`

Cycles: 33 — `ENTER` = 1 + (Q·E) (Table 4-36, p. 4-5). A non-stack-offset source flushes the cache unconditionally while MSP > SHAD (p. 3-19 pseudocode; p. 3-20 item 2): MSP 0x180 down to SHAD 0x100 is 0x80 = 128 bytes = 8 whole 16-byte blocks (each iteration writes `memory[MSP-16]` … `memory[MSP-4]` and does `MSP-=16`; an inexact distance would round up to a whole block). Q = 4 (model choice, README) ⇒ 1 + 4·8 = 33.

Encoding: Three-parcel monadic, opcode[5:0] = 0x00, `smode` = 0xF (`$data`, immediate) and subcode 0x9 = ENTER (p. 1-23; Table 1-19 p. 1-24; Table 1-21 p. 1-25); parcels 2–3 = 0x000000c0, a 32-bit `word32` operand (Table 3-2 p. 3-4).

Transition: A non-stack-offset source: the stack cache is flushed unconditionally while MSP > SHAD, i.e. 0x180 down to 0x100 — cache write-back traffic, not an architectural store — and then `SHAD = MSP = SP = target` = 0x000000c0 (p. 3-19 pseudocode; Description item 2, p. 3-20). Both SP and MSP move to 0x000000c0, which is what "the stack cache is set empty" means (p. 1-5: MSP is the address above the highest cached word).

L05. `HRI pc=000c insn=80df0000 sp=000000c0>000000d0 msp=000000c0>000000d0 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=2`

Cycles: 2 — `POPN` min=max=2 (Table 4-32, p. 4-3).

Encoding: Three-parcel monadic POPN: `smode` = 0xD (`stk32`, Table 3-2 p. 3-4), subcode 0xF (Table 1-19 p. 1-24; p. 3-38), operand 0x00000010.

Transition: `SHAD = CSP = CSP + 16` = 0x000000d0; CSP = SP and the new SP 0x000000d0 exceeds MSP 0x000000c0, so `MSP = SP` = 0x000000d0 (p. 3-38). This is the only line in the directory where POPN raises MSP; a model that never updated MSP here would differ on this line and the next.

L06. `HRI pc=0012 insn=2c020000 sp=000000d0>000000d0 msp=000000d0>000000d0 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `NOP` min=max=1 (Table 4-32, p. 4-3).

Encoding: Niladic `0x0B`/`0x002` (Table 1-17 p. 1-22; p. 3-35). Parcel 0x2c02.

Transition: No operation; the run ends after it at PC = 0x00000014 = image length (README, stop rule 2).

## Manual ambiguities and the choices they forced

- p. 3-19's pseudocode sets `SHAD = MSP = SP = target` for a non-stack-offset ENTER, while p. 3-20's Description item 2 says only that "the stack cache is set empty at the completion of ENTER". An empty cache means MSP = SP (p. 1-5: MSP holds the address above the highest cached word), so MSP := 0x000000c0 is taken. A model that left MSP at 0x00000180 would differ on this line and on the POPN after it, so the choice is visible in the data.

- POPN's rule is printed as `if ((CSP = SP) && (CSP > MSP)) MSP = SP` (p. 3-38) — it compares the *new* CSP and applies only when CSP = SP. Here PSW bit 9 = 1 makes CSP = SP (Table 1-8 sheet 2, p. 1-15), so the condition is live.

- Table 1-19's row header is printed `subcode[9:3]` although the table has two rows only, while the three-parcel monadic layout puts a 4-bit subcode in bits 3:0 (p. 1-23). The Chapter 3 encoding blocks use the 4-bit value (0x9 = ENTER, 0xF = POPN, pp. 3-20, 3-38), which is what is encoded; the header is a printed defect (`docs/isa_inventory.md` §7.3 item 4).

- The unconditional flush of the second ENTER is not visible in the fixed line: the line reports one architectural destination write, and a write-back of cache entries is not one. The same is true when CONFIG bit 18 leaves the stack cache disabled (its reset value, p. 1-36), so no line of this trace depends on cache policy.
