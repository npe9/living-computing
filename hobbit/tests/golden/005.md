# 005 — Conditional jumps taken and not taken: `JMPTN` jumps when PSW.F = 1 and does not when PSW.F = 0

This trace fixes CMPEQ's and CMPGT's effect on PSW.F (p. 3-13) and the
conditional jumps' use of that flag (p. 3-28), together with the one-parcel
`pcrel10` target rule of p. 1-22 and p. 1-27. The same mnemonic, `JMPTN`,
appears twice: once with F = 1, where it jumps, and once with F = 0, where it
does not. Nothing here was produced or checked by `bsv/`, `asm/` or `sem/`.

The manual is explicit that the *flag* decides and the trailing letter does
not: `JMPT: if (PSW.F) PC = &dst`, `JMPF: if (!PSW.F) PC = &dst`, and "A
branch prediction bit is available for the conditional jumps to indicate that
the jump more likely will (Y), or will not (N) be taken" (p. 3-28). The first
`JMPTN` is therefore taken while its prediction says not-taken, and the second
is not taken; a record of retired instructions shows the decisions and cannot
show the predictions.

The image is 6 word(s) = 24 byte(s); the program is 12 instruction(s), of which 10 retire in this run.

## Pre-state

Every run in this directory starts from the single pre-state fixed in
`README.md`:

| register | value | why |
|---|---|---|
| PC | `0x00000000` | reset start address, p. 1-36 |
| PSW | `0x00000200` | bit 9 = 1 makes SP the CSP (Table 1-8 sheet 2, p. 1-15); every other bit 0: kernel level, physical addressing, interrupts inhibited (IPL 0), tracing off |
| CONFIG | `0x00000000` | reset value: all caches disabled, demand prefetch, PC extension 0 (p. 1-36, p. 1-10) |
| SP | `0x00000100` | quad-aligned (p. 1-17) |
| MSP | `0x00000180` | quad-aligned, `SP <= MSP <= SP+256` (p. 1-13) |
| SHAD | `0x00000100` | p. 1-15: a direct write of PSW bit 9 requires SHAD to be updated to the new SP |
| ISP | `0x00000200` | quad-aligned (p. 1-12); never used, because PSW bit 9 selects SP |
| VB | `0x00000000` | never read inside a trace |
| memory | image at address 0, `0x00000000` elsewhere | `README.md`, "Memory" |

SP and MSP are quad-aligned stack pointers whose low 4 bits do not exist
(p. 1-17, p. 1-13), so no operand in these programs can be misaligned. PSW.F
is 0 in the pre-state (Table 1-8 sheets 1–3, pp. 1-14 to 1-16), so the first
flag the run sees is the one L02 sets.

## Retirement lines

One line per retired instruction, in program order, in the fixed HRI format.
`Lnn` numbers are used only by this document; the `.trace` file holds the same
lines without them.

Cycle accounting: `MOV`, `CMPEQ`, `CMPGT`, `ADD`, `ADD3` and `NOP` are 1 cycle each (Table 4-32, p. 4-3; its `CMP` row is the only timing the manual gives the compares, timing_tables.md §6 item 3); conditional jumps use Table 4-35 (p. 4-5). The p. 4-1 assumptions are adopted, so no fetch, operand-access or data-type delay is added. L02 reads the word L01 wrote, which violates p. 4-1's no-hazard assumption; section 4.2 prints no hazard penalty row, so the base stands. A/D/Q do not enter this program.

L01. `HRI pc=0000 insn=71400000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000100 data=0000000a mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3). L02's read of this word is a data hazard; no printed hazard row, so the base stands.

Encoding: One-parcel `MOV.CS`, opcode `0x1C`, `imm5`=10 in bits 9:5 (sign-extended 5-bit constant, p. 1-21; Table 3-2 p. 3-4), `stk5`=0 in bits 4:0 (Table 1-15 p. 1-22; p. 3-32). Parcel 0x7140.

Transition: `dst = src` (p. 3-32) makes *(CSP+0) = *(0x00000100) equal 0x0000000a; SP and MSP unchanged. This is the value both comparisons read.

L02. `HRI pc=0002 insn=41400000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — the `CMP` row, min=max=1 (Table 4-32, p. 4-3), is the manual's only timing for `CMPEQ` (timing_tables.md §6 item 3).

Encoding: One-parcel `CMPEQ.CS`, opcode `0x10`, `imm5`=10 in bits 9:5, `stk5`=0 in bits 4:0 (Table 1-15 p. 1-22; p. 3-13 row `2 0x10 CMPEQ imm5, stk5`). Parcel 0x4140.

Transition: `src1 rel src2 ? PSW.F = 1 : PSW.F = 0` with src1 in the source field and src2 in the destination field (p. 3-13 and its Notes): 10 == *(CSP+0) = 0x0000000a, so PSW.F := 1. No memory write and no SP/MSP change; the flag is not a field of the fixed line, which is why the two `JMPTN` lines that follow are the evidence for it.

L03. `HRI pc=0004 insn=18030000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=3`

Cycles: 3 — Table 4-35 (p. 4-5), row `Incorrect prediction, jump after compare` = 3. The prediction is N (not taken) but PSW.F = 1 makes the jump taken, and the compare at 0x0002 immediately precedes the branch. p. 4-7 lets a one-parcel branch fold into the preceding CMPEQ, but Table 4-35 prints no folded row for an incorrect prediction 1–3 instructions after compare (timing_tables.md §6 item 9); 3 is the table's only cost for this case. It is the flush/refill interval; the folded branch's own execution is 0 (p. 4-3).

Encoding: One-parcel `JMPTN`, opcode `0x06`, `pcrel10`=3 in bits 9:0 (Table 1-15 p. 1-22; p. 3-28 row `2 0x06 JMPTN pcrel10`). Sign-extended, doubled (p. 1-22) and added to the address of the instruction (p. 1-27): target = 0x0004 + 6 = 0x000a. Parcel 0x1803.

Transition: `JMPT: if (PSW.F) PC = &dst` (p. 3-28). F is 1 from L02, so this branch is **taken**: PC = 0x000a and the parcels at 0x0006 and 0x0008 are never retired, which is what their absence from this file records. The trailing `N` is the static prediction (p. 3-28, p. 1-33) — the branch is taken against it — and prediction changes no architectural state. No write.

L04. `HRI pc=000a insn=48200000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — the `CMP` row, min=max=1 (Table 4-32, p. 4-3), is the manual's only timing for `CMPGT` (timing_tables.md §6 item 3).

Encoding: One-parcel `CMPGT.CS`, opcode `0x12`, `imm5`=1 in bits 9:5, `stk5`=0 in bits 4:0 (Table 1-15 p. 1-22; p. 3-13 row `2 0x12 CMPGT imm5, stk5`). Parcel 0x4820.

Transition: `PSW.F = signed(src1 > src2)` with src1 = 1 (source field) and src2 = *(CSP+0) = 0x0000000a (destination field) (p. 3-13): 1 > 10 is false, so PSW.F := 0. No write. This line is reached only because L03 jumped, so its presence already proves the taken branch.

L05. `HRI pc=000c insn=18030000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=0`

Cycles: 0 — Table 4-35 (p. 4-5), row `Correct prediction, folded` = 0. The prediction is N and PSW.F = 0 makes the jump not taken, so the prediction is correct; the previous CMPGT (opcode 0x12) is a one-parcel non-jump outside 0x00–0x07, so the p. 4-7 rule folds the branch.

Transition: `JMPT: if (PSW.F) PC = &dst` (p. 3-28). F is 0 from L04, so this branch is **not taken**: PC = 0x000e and the target 0x0012 is not entered here. Same opcode, same `pcrel10`, same prediction letter as L03, opposite outcome: the only difference is PSW.F, which is exactly what this pair pins. No write.

## Manual ambiguities and the choices they forced

- The manual separates the decision from the prediction and this trace exercises the separation: `JMPT` jumps **iff** `PSW.F = 1` (p. 3-28), while the trailing `Y`/`N` only "indicates that the jump more likely will (Y), or will not (N) be taken" (p. 3-28; prediction rules p. 1-33). L03 is a `JMPTN` taken in spite of its `N`, and L05 is a `JMPTN` not taken. An implementation that treated the letter as the decision would skip L04 and fall through L05's target, changing four later records; this trace is built so that mistake cannot pass.

- CMPEQ's operand order is stated only in the Notes — "src1 is specified in the source operand field. src2 is specified in the destination operand field" (p. 3-13) — because the printed Operation line is `srcl rel src2?`. `CMPEQ $10, R0` compares the immediate 10 with *(CSP+0); the operands are equal here, so a swapped reading would still produce F = 1 on L02.

- CMPGT's order matters here: `PSW.F = signed(src1 > src2)` (p. 3-13) with src1 = the immediate 1 and src2 = *(CSP+0) = 10 gives false, so F = 0 on L04 and L05 falls through. A model that compared src2 > src1 would set F = 1, take the branch at 0x000c, and show the record at 0x0012 next instead of the `ADD $2, R0` record at 0x000e.

- The manual gives no way to set PSW.F except the compare instructions and a `CPU`-prefixed write to PSW (Table 1-22 p. 1-26, p. 3-14), and the escape is outside the first milestone, so two compares are used: equality for F = 1 and signed greater-than for F = 0.

- A taken one-parcel jump's target is computed from "the address of the instruction" (p. 1-27) with the offset sign-extended and doubled (p. 1-22); both targets here (0x000a, 0x0012) follow that rule, and the manual prints no worked one-parcel example.

- The parcels at 0x0006 and 0x0008 are never retired. They are kept so the taken branch has something to jump over — a run that fell through L03 would show an `ADD $1, R0` record at 0x0006, which the trace does not contain. The NOPs at 0x0014 and 0x0016 are padding that makes the last instruction end exactly at the image end.
