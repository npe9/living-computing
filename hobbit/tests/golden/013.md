# Golden 013 — one-parcel Table 1-15 row 11: MOV.CS, SHL3.CS, SHR3.CS, MOVA.SS

Image (8 bytes):

```text
73e37883
7c837482
```

Reference pre-state as in 007: `SP = 0x00000100`, `MSP = 0x00000180`,
`PSW = 0x00000200` (bit 9: CSP = SP, p. 1-14), `SHAD = 0x100`.
The integer accumulator is the word at `CSP + 4 = 0x00000104`
(p. 1-7, Figure 1-4), not a register.

The four instructions are all in Table 1-15 row 11 (printed p. 1-22),
opcodes `0x18`..`0x1F`.  The one-parcel layout is bit 15 = 0,
opcode[4:0] in bits 14:10, the 5-bit source in bits 9:5 and the 5-bit
destination in bits 4:0 (p. 1-21).  The `stk5` destination is
zero-extended and multiplied by four (p. 1-21, p. 1-22); `imm5` is
sign-extended, `uimm5` is unsigned, and the shift count is the `uimm5`
value itself (pp. 3-41, 3-42).

| pc | parcel | instruction | encoding |
|---|---|---|---|
| `0000` | `73e3` | `MOV $-1,R12` | opcode `0x1C` = `MOV.CS`; `src5 = 0x1F` = `-1`; `dst5 = 3` → `SP+12 = 0x10c` |
| `0002` | `7883` | `SHL3 $4,R12` | opcode `0x1E` = `SHL3.CS`; `uimm5 = 4`; `dst5 = 3` → `0x10c` |
| `0004` | `7c83` | `SHR3 $4,R12` | opcode `0x1F` = `SHR3.CS`; `uimm5 = 4`; `dst5 = 3` → `0x10c` |
| `0006` | `7482` | `MOVA R16,R8` | opcode `0x1D` = `MOVA.SS`; `src5 = 4` → `R16 = 0x110`; `dst5 = 2` → `R8 = 0x108` |

L01. `HRI pc=0000 insn=73e30000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=0000010c data=ffffffff mask=0f trap=0 cyc=1`
Cycles: 1 — `MOV` is 1 in Table 4-32 (p. 4-3).  The one-parcel
`MOV imm5, stk5` form writes the sign-extended `imm5` to the `stk5`
address `SP+12 = 0x10c`; `0x1F` sign-extends to `0xffffffff`.
Source: p. 3-32, Table 1-15 p. 1-22, Table 4-32 p. 4-3.

L02. `HRI pc=0002 insn=78830000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000104 data=fffffff0 mask=0f trap=0 cyc=1`
Cycles: 1 — `SHL3` is 1 in Table 4-32 (p. 4-3).  p. 3-41:
"SHL3: Acc = dst << Unsigned(src)"; the destination word at `0x10c`
is `0xffffffff`, the `uimm5` count is 4, and zeros fill the vacated
low bits, so the accumulator at `CSP+4 = 0x104` receives `0xfffffff0`.
The destination is left unchanged and there is no other write.  The
page states no C/V/F effect, so the PSW is unchanged.
Source: p. 3-41, Table 1-15 p. 1-22, p. 1-7, Table 4-32 p. 4-3.

L03. `HRI pc=0004 insn=7c830000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000104 data=ffffffff mask=0f trap=0 cyc=1`
Cycles: 1 — `SHR3` is 1 in Table 4-32 (p. 4-3).  p. 3-42:
"SHR3: Acc = dst >> src", and "the sign bit of the destination is
copied as bits are shifted rightward" — an arithmetic shift.  The
destination is still `0xffffffff` at `0x10c` (L02 wrote only the
accumulator), so `-1 >> 4` sign-fills to `0xffffffff` at `0x104`.
A logical shift would have produced `0x0fffffff`; this line
discriminates the two.  The destination is unchanged and the PSW is
not affected (the page states no C/V/F effect).
Source: p. 3-42, Table 1-15 p. 1-22, p. 1-7, Table 4-32 p. 4-3.

L04. `HRI pc=0006 insn=74820000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000108 data=00000110 mask=0f trap=0 cyc=1`
Cycles: 1 — `MOVA` is 1 in Table 4-32 (p. 4-3).  p. 3-33: the address
of the source operand is stored in the destination.  Both fields are
`stk5` word stack offsets in the one-parcel form: `R16` is
`SP+16 = 0x110` and `R8` is `SP+8 = 0x108`, so `0x00000110` is
written at `0x108`.
Source: p. 3-33, Table 1-15 p. 1-22, Table 4-32 p. 4-3.

The image ends at `0x0008`, which is the address after L04, so the
run stops at the image end (adjudication convention C1) with no
padding fetched.
