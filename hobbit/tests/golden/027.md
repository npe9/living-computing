# Golden 027 — the last instructions of a mapped page retire: a fetch fault is an instruction's own

The third golden on the privileged harness (`README.md`, "The privileged
harness").  It pins `docs/conformance_1to1.md` §1d row 13, found at
record 287,416,554 of the s9term join on the core (`docs/p9boot.md`,
"The boot on the core"): `/boot` calls `0x1ffc`, two `NOP`s at the end of
a mapped page, with the page from `0x2000` not yet mapped.  The
reference retires both `NOP`s and takes the fetch fault at `0x2000`; the
core took it at `0x1ffc`.  The core's prefetch decode unit reads a window
of three 8-byte lines (up to 16 bytes past the PC) and faulted the
instruction if any line of the window faulted.

The printed basis: a fetch fault is the exception of "an address
translation for ... fetching an instruction" (p. 2-3), and the event
sequence saves the PC of the faulted instruction (p. 1-38).  An
instruction whose own parcels are all in a valid page makes no faulting
fetch; the window beyond it is the part's prefetch, which p. 2-3 lets it
make without effect (§1c).

## How this file was derived

By hand, before the core ran the image; `sem/` reproduced every line.
The `JMP` was assembled with `asm/hobbit_asm.py` (`JMP *$0xffc`,
`80f3 0000 0ffc`).

## Image (`027.hex`)

1024 words, so the image ends at the page boundary `0x1000`: four
copies of a 256-word block (see the last section), of which only these
words are used:

| word address | word | parcels (31:16, 15:0) |
|---|---|---|
| `0x0000` | `80f30000` | `80f3`, `0000` |
| `0x0004` | `0ffc2c02` | `0ffc`, `2c02` |
| `0x0ffc` | `2c022c02` | `2c02`, `2c02` |

Every other word is `00000000` or a copy of these at `+0x400`, `+0x800`
or `+0xc00`, never fetched.

## Program

| address | parcels | instruction |
|---|---|---|
| `0x0000` | `80f3 0000 0ffc` | `JMP *$0xffc` -- three-parcel monadic, mode `0xF`, subcode 3 (Table 1-19 p. 1-24; p. 3-28) |
| `0x0006` | `2c02` | `NOP` -- padding, never executed |
| `0x0ffc` | `2c02` | `NOP` |
| `0x0ffe` | `2c02` | `NOP` -- the last parcel of page 0 |

## Pre-state

Golden 025's (PSW `0x00010200`, STB `0x1000`, page 0 mapped writable,
page 3 read-only, every other page -- page 1 included -- invalid; VB
`0x40`, `*(VB+4) = 0x20`).  The run ends when the next PC reaches the
image end, `0x1000` (`README.md`); the fetch there is never made.

## Retirement lines

L01. `HRI pc=0000 insn=80f30000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `JMP` unfolded = 1 (Table 4-32 Max, p. 4-3 note); a
three-parcel jump does not fold (p. 4-7), as golden 019's.

Transition (p. 3-28): PC = `0x0ffc`.

L02. `HRI pc=0ffc insn=2c020000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `NOP` min=max=1 (Table 4-32, p. 4-3).

Transition (p. 3-34): nothing.  Its one parcel is in page 0; no fault.

L03. `HRI pc=0ffe insn=2c020000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `NOP` min=max=1 (Table 4-32, p. 4-3).

Transition (p. 3-34): nothing.  The next PC is `0x1000`, the image end.

## Discriminating check (observed 2026-11-24)

The core's PDU before the fix (`HobbitDecode.bsv` as of c35c3e53: the
instruction faults if any of the window's three lines faults), the golden
rebuilt and run, and the fixed file restored byte for byte:

| injection | observed |
|---|---|
| any faulting line of the window faults the instruction | fails at L02: `pc=0ffc insn=00000000 ... we=1 addr=00000100 data=00000ffc mask=0f trap=1 cyc=8` -- the fetch fault taken at `0x0ffc` (the boot's symptom), then the handler at `0x20` and the run repeats until the harness's guard ends it |

A first version of the fix, without the S2 change (a faulting line also
counts as present), retired only L01: the line at `0x1000` was a miss
that a demand fill could never fill, so the fetch at `0x0ffc` waited for
it forever.

The image is four copies of one 256-word block because the golden
harness's memory is 256 words and wraps (`HobbitBus.bsv`
`mkHobbitBusMem`): the copies make the wrapped load agree with the
1024-word image `sem/` reads, and keep the run's end at `0x1000`.
