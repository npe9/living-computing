# 002 — Three-parcel ADD and SUB with 16-bit immediate and stack-offset operands

This trace fixes the three-parcel form: bits 15:14 = `10`, opcode[5:0] in
bits 13:8, `smode` in bits 7:4, `dmode` in bits 3:0, source in parcels 2–3
and destination in parcels 4–5 (p. 1-23, Table 1-18 p. 1-24), with the
16-bit operands sign-extended in immediate and offset modes (p. 1-23). It
executes one ADD and one SUB in the general (`gen16`) form, which the
one-parcel `imm5` form cannot express. Mode codes are Table 1-21 (p. 1-25):
`0xD` = `Roffset:W`, `0xF` = `$data`.

The image is 7 word(s) = 28 byte(s); the program is 8 instruction(s), of which 8 retires in this run.

## Pre-state

Every run in this directory starts from the single pre-state fixed in
`README.md`:

| register | value | why |
|---|---|---|
| PC | `0x00000000` | reset start address, p. 1-36 |
| PSW | `0x00000200` | bit 9 = 1 makes SP the CSP (Table 1-8 sheet 2, p. 1-15); every other bit 0: kernel level, physical addressing, interrupts inhibited (IPL 0), tracing off |
| CONFIG | `0x00000000` | reset value: all caches disabled, demand prefetch, PC extension 0 (p. 1-36, p. 1-10) |
| SP | `0x00000100` | quad-aligned (p. 1-17) |
| MSP | `0x00000180` | quad-aligned, `SP <= MSP <= SP+256` (p. 1-13) |
| SHAD | `0x00000100` | p. 1-15: a direct write of PSW bit 9 requires SHAD to be updated to the new SP |
| ISP | `0x00000200` | quad-aligned (p. 1-12); never used, because PSW bit 9 selects SP |
| VB | `0x00000000` | never read inside a trace |
| memory | image at address 0, `0x00000000` elsewhere | `README.md`, "Memory" |

SP and MSP are quad-aligned stack pointers whose low 4 bits do not exist
(p. 1-17, p. 1-13), so no operand in these programs can be misaligned.

## Retirement lines

One line per retired instruction, in program order, in the fixed HRI format. `Lnn` numbers are used only by this document; the `.trace` file holds the same lines without them.

L01. `HRI pc=0000 insn=71400000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000100 data=0000000a mask=0f trap=0`

Encoding: One-parcel `MOV.CS`, opcode `0x1C`, `imm5`=10 in bits 9:5, `stk5`=0 in bits 4:0 (Table 1-15 p. 1-22; p. 3-32). The 5-bit immediate is sign-extended, so 10 is the value 10 (p. 1-21). Parcel 0x7140.

Transition: *(0x00000100) = 0x0000000a; SP and MSP unchanged (p. 1-6).

L02. `HRI pc=0002 insn=a3fd0064 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000100 data=0000006e mask=0f trap=0`

Encoding: First parcel 0xA3FD: bits 15:14 = `10` (three parcels, p. 1-23), opcode[5:0] = 0x23 = ADD (Table 1-18 p. 1-24; p. 3-5 row `6 0x23 ADD gen16, gen16`), smode = 0xF (`$data`, immediate) and dmode = 0xD (`Roffset:W`, word stack offset) per Table 1-21 p. 1-25. Parcel 2 = 0x0064 is the source, parcel 3 = 0x0000 the destination; both are sign-extended 16-bit fields in immediate and offset modes (p. 1-23).

Transition: `dst += src` (p. 3-5): *(CSP+0) = 0x0000000a + 0x00000064 = 0x0000006e. The destination field is a byte offset from CSP in the `Roffset:W` mode (p. 1-27), so 0x0000 means SP itself. One word write at 0x00000100.

L03. `HRI pc=0008 insn=a0fd0070 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000100 data=fffffffe mask=0f trap=0`

Encoding: First parcel 0xA0FD: opcode[5:0] = 0x20 = SUB (Table 1-18 p. 1-24; p. 3-43 row `6 0x20 SUB gen16, gen16`), smode 0xF, dmode 0xD. Source 0x0070 = 112, destination 0x0000 (p. 1-23, Table 1-21 p. 1-25).

Transition: `dst -= src` (p. 3-43): 0x0000006e - 0x00000070 = -2 = 0xfffffffe at 0x00000100. The result is a signed word and the destination is a word, so no truncation applies. PSW.C is set on the unsigned borrow and PSW.V cleared (p. 3-43); neither is a field of the fixed line.

L04. `HRI pc=000e insn=28a20000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000108 data=00000014 mask=0f trap=0`

Encoding: One-parcel `MOV.WS`, opcode `0x0A`, `wai5`=5 (5*4 = 20) in bits 9:5, `stk5`=2 (offset 8) in bits 4:0 (Table 1-15 p. 1-22; p. 3-32; Table 3-2 p. 3-4). Parcel 0x28a2.

Transition: *(0x00000108) = 0x00000014. No earlier instruction of this program touched `CSP+8`, so this is a plain store; it gives the next SUB a destination word independent of the accumulator word at 0x00000104, which this program never writes.

L05. `HRI pc=0010 insn=a0dd0000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000108 data=00000016 mask=0f trap=0`

Encoding: First parcel 0xA0DD: opcode[5:0] = 0x20 (SUB), smode `0xD`, dmode `0xD` — both operands are word stack offsets (Table 1-18 p. 1-24; Table 1-21 p. 1-25). Source 0x0000 = *(CSP+0) = 0xfffffffe, destination 0x0008 = *(CSP+8) = 0x00000014.

Transition: `dst -= src` = 20 - (-2) = 22 = 0x00000016, written to 0x00000108. This is the arithmetic test of the trace: it distinguishes `dst - src` from `src - dst` (which would be -22) and from the printed `dst -= dst` typo pattern of the ADD page.

L06. `HRI pc=0016 insn=2c020000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0`

Encoding: Niladic opcode `0x0B`, subcode `0x002` (Table 1-17 p. 1-22; p. 3-35). Parcel 0x2c02.

Transition: No operation, no write.

L07. `HRI pc=0018 insn=2c020000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0`

Encoding: Identical NOP encoding (Table 1-17 p. 1-22; p. 3-35).

Transition: No operation. Two NOPs are enough to make the last instruction end at the image end, 0x0000001c.

L08. `HRI pc=001a insn=2c020000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0`

Encoding: Identical NOP encoding (Table 1-17 p. 1-22; p. 3-35).

Transition: No operation; the run ends after it at PC = 0x0000001c = the image length (README, stop rule 2).

## Manual ambiguities and the choices they forced

- The 16-bit source and destination fields are sign-extended only when used in immediate or offset modes; in absolute mode the upper half comes from CONFIG bit 17 (p. 1-23). Both operands here are immediate or stack-offset, so no CONFIG question arises and no absolute address is encoded — the trace therefore also does not depend on the reset value of CONFIG.

- `SUB` prints `dst -= src` in both its Operation and its Description lines (p. 3-43), unlike ADD (p. 3-5); no conflict had to be resolved for SUB.

- The manual defines `gen16` as "any of the following modes with a value that can fit in n-bits: absolute, immediate, stack offset or stack offset indirect" (Table 3-2 p. 3-4) and prints `ADD gen16, gen16`. It does not say whether an assembler that meets `ADD $100, R0` must choose the six-byte form or reject it; the six-byte form is what the tables provide for a 100-byte immediate, and it is what is encoded here.

- PSW.C and PSW.V are architectural results of both dyadic operations (pp. 3-5, 3-43), but the fixed line has no field for them. The manual also never defines the *unsigned borrow* condition of SUB precisely (p. 3-43 gives only the phrase `"unsigned borrow" ? PSW.C = 1`), so neither the trace nor the `.md` claims a C value.
