# Golden 026 — ENTER's store check: exception 8 after the flush, SP and MSP unchanged

The second golden on the privileged harness (`README.md`, "The
privileged harness"; golden 025 is the first).  It pins
`docs/conformance_1to1.md` §1d row 11, found at record 22,533,287 of the
s9term boot, where `/boot`'s `ENTER` lowers SP by `0x1020` into a user
stack page the kernel has not mapped yet.  The reference takes the
exception and leaves SP and MSP alone; the kernel maps the page and the
`ENTER` restarts.  The core had executed the `ENTER` and moved SP and MSP
into the unmapped page.

p. 3-21 (read from the page image): "If virtual addressing is enabled,
the target address and the new MSP, if the MSP is updated, are checked
to verify that stores are valid at the current execution level.  If the
addresses are not valid, a read fault exception, exception type 8, or
MMU table walk fault 0xB, is flagged for ENTER.  The exception is
processed after any stack flushing is completed."

## How this file was derived

By hand, from the pages cited, before the core ran the image; `sem/`
reproduced every line.  A first try with the fixed pre-state (SP
`0x100`) was refused by `sem/` as unpredictable, correctly: `ENTER
R-512` from SP `0x100` wraps above SP (p. 3-21), so SP was moved to
page 5.

## Program

The one-parcel stack-class `ENTER` is golden 019's `ENTER R-16`
(`0bfc`, p. 3-20) with the 10-bit word offset `0x380` = -128 words =
-512 bytes.  `NOP` is `0x2c02` (Table 1-17, p. 1-22).

| address | parcels | instruction |
|---|---|---|
| `0x0000` | `0b80` | `ENTER R-512` -- target `0x5100 - 0x200 = 0x4f00`, page 4 |
| `0x0002` | `2c02` | `NOP` -- must not retire |
| `0x0004` | `2c02` ×2 | `NOP` -- never executed |
| `0x0008` | `2c02` | `NOP` -- the handler, `*(VB+4)` |
| `0x000a` | `2c02` | `NOP` -- the image ends here |

## Pre-state

Golden 025's, with these differences:

* SP `0x5100`, MSP `0x5180`, SHAD = SP: the stack in page 5.
* The page table maps page 0 (`0x00000003` at `0x2000`) and page 5 to
  frame 5, writable (`0x00005003` at `0x2014`, Table 2-3 p. 2-7); every
  other page, page 4 included, is invalid.
* The word at `0x44` (`VB+4`) is `0x00000008`.

`sem/hobbit_sem.py --sp 0x5100 --msp 0x5180 --psw 0x10200 --isp 0x200
--vb 0x40 --system --stb 0x1000 --poke 44=00000008 --poke 1000=00002001
--poke 2000=00000003 --poke 2014=00005003`; `bsv/run_golden.sh 026`.

## Retirement lines

L01. `HRI pc=0000 insn=0b800000 sp=00005100>00005100 msp=00005180>00005180 we=0 addr=00000000 data=00000000 mask=00 trap=1 cyc=12`

Cycles: 12 — Table 4-36 (p. 4-5), the Exception row, 9 + D + A, with
the model's D = 2 and A = 1 (named choices: p. 4-2 prints no memory
terms; `docs/conformance_1to1.md`), the cost the record of an instruction
that takes an exception carries.  (Written as 0 when this
golden was first derived, on the claim that Chapter 4 prints no
exception cost; that was wrong, and the reference was corrected to 12
the same day, master 58332b49.)

Transition (p. 3-21, p. 1-38): the target `0x4f00` is the new SP.
`MSP - target = 0x280` exceeds SCSIZE (256 bytes, p. 1-6), so the
stack-offset form flushes (p. 3-19).  The target is checked as a store at
kernel level: page 4 has no valid entry, so exception 8 is flagged and
taken after the flush; the `ENTER` does not complete, and SP and MSP are
as before (`sp=00005100>00005100 msp=00005180>00005180`).  The sequence:
CSP = SP, so SP = SHAD = `0x5100`; the frame at `ISP-12` .. `ISP-4`
(page 0); PC = `*(VB+4)` = `0x8`.  The `NOP` at `0x0002` does not retire.

L02. `HRI pc=0008 insn=2c020000 sp=00005100>00005100 msp=00005180>00005180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `NOP` min=max=1 (Table 4-32, p. 4-3).

Transition (p. 3-34): the handler's first instruction; nothing.

L03. `HRI pc=000a insn=2c020000 sp=00005100>00005100 msp=00005180>00005180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `NOP` min=max=1 (Table 4-32, p. 4-3).

Transition (p. 3-34): nothing.  The image ends here.

## Discriminating check (observed 2026-11-24)

Each injected into `bsv/HobbitCore.bsv` alone, the golden rebuilt and run,
the file restored byte for byte from a saved copy:

| injection | observed |
|---|---|
| `enterFault` never fires (the check removed) | fails at L01, `sp` `00005100>00004f00` for `00005100>00005100`: the `ENTER` completes into page 4 and the `NOP`s retire there |
| `commit` does not wait on a trap not yet taken (`!trapPendR` removed) | **every line still matches** |
| the exception not held for the flush (`trapPending` = `trapPendR`) | **every line still matches** |

The last two are not pinned: the `NOP` behind the `ENTER` had not
reached EU_S3 by the time the sequence started, and the flush's effect
is not in any record field.  They rest on p. 3-21's text and on the
boot (§1d #11).
