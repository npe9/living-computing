# 003 — A CALL/RETURN pair with ENTER, one-parcel CALL and three-parcel RETURN

This trace fixes the CALL/RETURN pair (p. 3-9, p. 3-40), the
one-parcel PC-relative branch (`pcrel10`: sign-extended, multiplied by 2,
p. 1-22 and p. 1-27), the one-parcel stack class (`ENTER`, Table 1-16
p. 1-22) and the three-parcel monadic form (`RETURN stk32`, Table 1-19
p. 1-24). The return PC is saved in the word at CSP itself, the R0 slot
(p. 1-7, p. 1-31, p. 3-9).

The image is 4 word(s) = 16 byte(s); the program is 6 instruction(s), of which 6 retires in this run.

## Image (`003.hex`)

| word address | word | parcels (31:16, 15:0) |
|---|---|---|
| `0x0000` | `0c060bfc` | `0c06`, `0bfc` |
| `0x0004` | `2c0280d2` | `2c02`, `80d2` |
| `0x0008` | `00000010` | `0000`, `0010` |
| `0x000c` | `07fb2c02` | `07fb`, `2c02` |

Parcels are 2 bytes; the parcel at an even address occupies bits 31:16 of the word at that address and the parcel at the following address bits 15:0 (`README.md`, fixed image format).

## Pre-state

Every run in this directory starts from the single pre-state fixed in
`README.md`:

| register | value | why |
|---|---|---|
| PC | `0x00000000` | reset start address, p. 1-36 |
| PSW | `0x00000200` | bit 9 = 1 makes SP the CSP (Table 1-8 sheet 2, p. 1-15); every other bit 0: kernel level, physical addressing, interrupts inhibited (IPL 0), tracing off |
| CONFIG | `0x00000000` | reset value: all caches disabled, demand prefetch, PC extension 0 (p. 1-36, p. 1-10) |
| SP | `0x00000100` | quad-aligned (p. 1-17) |
| MSP | `0x00000180` | quad-aligned, `SP <= MSP <= SP+256` (p. 1-13) |
| SHAD | `0x00000100` | p. 1-15: a direct write of PSW bit 9 requires SHAD to be updated to the new SP |
| ISP | `0x00000200` | quad-aligned (p. 1-12); never used, because PSW bit 9 selects SP |
| VB | `0x00000000` | never read inside a trace |
| memory | image at address 0, `0x00000000` elsewhere | `README.md`, "Memory" |

SP and MSP are quad-aligned stack pointers whose low 4 bits do not exist
(p. 1-17, p. 1-13), so no operand in these programs can be misaligned.

## Retirement lines

One line per retired instruction, in program order, in the fixed HRI format. `Lnn` numbers are used only by this document; the `.trace` file holds the same lines without them.

Cycle accounting: `JMP` is 0 folded and 1 unfolded (Table 4-32 p. 4-3 prints min 0/max 1; the p. 4-3 note gives the two cases); `CALL` 1, `NOP` 1, `RETURN` 2 (Table 4-32, p. 4-3), `ENTER` 1 + (Q·E) (Table 4-36, p. 4-5) with E read as the number of 16-byte blocks moved by the pp. 3-19/3-20 flush loop. The p. 4-1 assumptions are adopted, so no Table 4-37/4-38/4-39/4-40 delay is added. Q=4 is a model choice, not a printed value (README, "Cycle model").

L01. `HRI pc=0000 insn=0c060000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — unfolded `JMP`: Table 4-32 (p. 4-3) prints min 0/max 1, and the p. 4-3 note gives 0 folded / 1 unfolded. Nothing precedes this instruction, so it cannot fold.

Encoding: One-parcel `JMP`, opcode `0x03` in bits 14:10 with the whole 10-bit `pcrel10` field in bits 9:0 (p. 1-21 monadic layout; Table 1-15 p. 1-22; p. 3-28). The field is sign-extended and multiplied by 2 (p. 1-22) and added to the address of the instruction (p. 1-27). Parcel 0x0c06.

Transition: PC = 0x0000 + 2*6 = 0x000c (p. 3-28, `PC = &dst`). No memory write; SP and MSP unchanged.

L02. `HRI pc=000c insn=07fb0000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000100 data=0000000e mask=0f trap=0 cyc=1`

Cycles: 1 — `CALL` min=max=1 (Table 4-32, p. 4-3). The return-PC store at CSP is a stack-offset write, captured in the stack cache under p. 4-1, so no A term is added.

Encoding: One-parcel `CALL`, opcode `0x01`, `pcrel10` = 0x3FB, which sign-extends to -5 (Table 1-15 p. 1-22; p. 3-9; p. 1-22). Parcel 0x07fb.

Transition: `*(CSP) = next PC` (p. 3-9): 0x0000000e is stored at 0x00000100, the PC save slot at CSP (p. 1-7, p. 1-31). PC = 0x000c + 2*(-5) = 0x0002. This line is the one place the return address becomes visible in the trace.

L03. `HRI pc=0002 insn=0bfc0000 sp=00000100>000000f0 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `ENTER` = 1 + (Q·E) (Table 4-36, p. 4-5). E = 0: MSP − target = 0x180 − 0x0f0 = 0x90 = 144 ≤ SCSIZE 256, so the p. 3-19 flush loop does not run and no 16-byte block is moved, so Q does not enter numerically (Q = 4 is a model choice, README). 1 + 0 = 1.

Encoding: One-parcel stack class: bits 15:14 = `00`, bits 14:10 = 0x02, the 8-bit stack offset in bits 9:2 and the 2-bit subcode in bits 1:0 (Table 1-16 p. 1-22; p. 3-19). Subcode 0 = ENTER; the field is 0xFF, which ENTER left-pads with ones and multiplies by 16 (footnote a, p. 3-20), giving -16. Parcel 0x0bfc.

Transition: CSP = SP is the stack-offset form: the flush is only as much as necessary, and MSP - target = 0x180 - 0x0f0 = 0x90 is below SCSIZE = 256, so nothing is written back (p. 3-19 pseudocode; p. 1-6). SP becomes 0x000000f0, MSP stays 0x00000180, SHAD becomes SP (p. 3-19), and PSW.E is set on completion (p. 3-20). Flush/refill traffic is cache traffic, not an architectural store, so the line reports no write.

L04. `HRI pc=0004 insn=2c020000 sp=000000f0>000000f0 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `NOP` min=max=1 (Table 4-32, p. 4-3).

Encoding: Niladic `0x0B`/`0x002` (Table 1-17 p. 1-22; p. 3-35). Parcel 0x2c02.

Transition: No operation. p. 3-4 forbids an instruction that rewrites SHAD from immediately following ENTER or RETURN; no instruction in this trace writes SHAD, so the rule is not triggered, and the NOP is here only to give the callee a second instruction and to keep the image an even number of parcels.

L05. `HRI pc=0006 insn=80d20000 sp=000000f0>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=2`

Cycles: 2 — `RETURN` min=max=2 (Table 4-32, p. 4-3). The p. 4-3 note makes the row complete: RETURNs are always indirect and take no indirection delay.

Encoding: Three-parcel monadic form: bits 15:14 = `10`, opcode[5:0] = 0x00 in bits 13:8, `smode` = 0xD (`Roffset:W`) in bits 7:4 and the 4-bit subcode 0x2 = RETURN in bits 3:0 (p. 1-23; Table 1-19 p. 1-24; Table 1-21 p. 1-25). Parcels 2–3 hold the 32-bit operand 0x00000010 (`stk32`, Table 3-2 p. 3-4). Third parcel pair is not shown in the `insn` field, which carries only the first two parcels.

Transition: `PC = *(CSP + src)` = *(0x000000f0 + 16) = *(0x00000100) = 0x0000000e, the word the CALL stored (p. 3-40). Then `SHAD = CSP = CSP + src` = 0x00000100; the low 4 bits of the offset are ignored when adjusting SP (p. 3-40) and are already 0. The new SP 0x00000100 does not exceed MSP 0x00000180, so MSP is unchanged. RETURN performs no architectural store of its own.

L06. `HRI pc=000e insn=2c020000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=1`

Cycles: 1 — `NOP` min=max=1 (Table 4-32, p. 4-3).

Encoding: Niladic `0x0B`/`0x002` (Table 1-17 p. 1-22; p. 3-35). Parcel 0x2c02.

Transition: No operation. It is the return point of the CALL at 0x000c and the last instruction of the image, so the run ends after it at PC = 0x00000010 (README, stop rule 2).

## Manual ambiguities and the choices they forced

- The base of a `pcrel10` branch is "the address of the instruction" (p. 1-27). For a one-parcel instruction that is its own parcel address, which is what is used: the JMP at 0x0000 reaches 0x000c and the CALL at 0x000c reaches 0x0002. An implementation that added the offset to the *following* parcel would send the JMP to 0x000e and the CALL to 0x0004, changing the pc of the next two lines and the return address the CALL stores.

- Only the one-parcel ENTER is used, because p. 3-21 requires `|offset| > SCSIZE` for the six-byte ENTER with a stack-offset source, while the one-parcel footnote (p. 3-20a) allows -16..-4096. The manual does not say what the six-byte form does with -16; the trace avoids the question.

- RETURN's operand is a byte offset added to CSP (p. 3-40, `PC = * (CSP + src)`), and the three-parcel field is a 32-bit value (`stk32`, Table 3-2 p. 3-4), so 16 is the frame size in bytes, not the word offset R4 = 4. p. 3-40's Notes show the two forms differ only in whether the low 4 bits are ignored when adjusting SP.

- The manual states no instruction that ends a program. The run's end is therefore a property of the harness (image end, README). The CALL returns to the NOP at 0x000e, which is the last instruction, so that the final instruction's last parcel is the final parcel of the image.

- The CALL's return address is stored at CSP with no stack-pointer adjustment (p. 3-9, p. 1-31); the manual does not restate whether that store also raises MSP. p. 1-13 lists the instructions that update MSP implicitly — CATCH, CRET, ENTER, POPN, RETURN — and CALL is not among them, so MSP is unchanged on the CALL line.
