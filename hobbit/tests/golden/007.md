# Golden 007 — `MUL` (three-parcel, immediate source)

Image (8 bytes, two 32-bit words):

```text
70e2a6fd
00060008
```

Reference pre-state: `PC=0, SP=0x100, MSP=0x180, PSW=0x200`, all data
memory zero.  Parcel at byte 0 is `0x70e2`, so the first instruction is
one parcel; the second starts at byte 2 and is three parcels.

The first instruction is `MOV $7,R8`.  Table 1-15 (p. 1-22) gives
`opcode[4:0]=0x1C` for `MOV imm5,stk5`; `7 << 5` is the source field
and stack offset 8 is field `8/4 = 2`, so the parcel is
`(0x1C<<10)|(7<<5)|2 = 0x70e2`.  p. 1-21 says "5-bit immediate fields
are sign extended and 5-bit stack offset fields are zero extended", and
p. 1-22 says the stack offset is multiplied by four, so the destination
is `SP+8 = 0x00000108`.

The second instruction is `MUL $6,R8`.  Table 1-18 (p. 1-24) gives
`MUL` opcode `0x26`; the first parcel is
`0x8000|(0x26<<8)|(0xF<<4)|0xD = 0xa6fd`, with source field `0x0006`
(mode 0xF, immediate) and destination field `0x0008` (mode 0xD, word
stack offset).  p. 3-34 defines the operation as `dst *= src` and sets
C on unsigned overflow and V on signed overflow of the destination.

L01. `HRI pc=0000 insn=70e20000 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000108 data=00000007 mask=0f trap=0 cyc=1`
Cycles: 1 — `MOV` is 1 in Table 4-32 (p. 4-3); the word write is `7`
at `R8 = SP+8` with a full word mask.
Source: p. 3-32, Table 1-15 p. 1-22, Table 4-32 p. 4-3.

L02. `HRI pc=0002 insn=a6fd0006 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000108 data=0000002a mask=0f trap=0 cyc=20`
Cycles: 20 — Table 4-33 (p. 4-4) prints `MUL` only as a data-dependent
range, Min 3 / Max 20, and nowhere prints the dependence; the model
takes the printed maximum (`MUL_CYC`), a named choice, not a manual
value.  `7 * 6 = 42 = 0x2a`; both the unsigned product (42) and the
signed product (42) fit the 32-bit destination, so C and V are cleared
(p. 3-34).  Flags are state, not HRI fields.
Source: p. 3-34, Table 1-18 p. 1-24, Table 4-33 p. 4-4.
