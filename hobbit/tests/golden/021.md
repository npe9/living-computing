# Golden 021 — DQM with a source in the stack cache or in memory

p. 3-18: "Double- or quad-word move moves either two or four contiguous
words from the source to the destination. The size of the transfer is
determined by the destination address mode field."  Golden 019 pins the
constant source; this trace pins the other one, a *block* source, in all
four of Table 4-34's placements: stack cache to memory, memory to memory,
memory to stack cache, stack cache to stack cache.

1st Edition Plan 9's C compiler copies structures with this instruction
(`DQM *R24, *R24` -- `zc` executes it compiling any file), and the
Bluespec core refused a block source until 2026-11-20.

The image is 20 words = 80 bytes; 14 records retire.

## How this file was derived

By hand from the printed pages, before either model ran it.  The cycle
rows are Table 4-34's with the README's named parameters (D = 2), and
one of them is a stated choice rather than a printed value: the
memory-to-memory quad word is printed `8.S`, `S` is undefined (p. 4-2),
and it is read as a single-word access (L05).  Neither `asm/` nor `sem/`
nor `bsv/` produced or corrected any field.

## Program

`DQM` is opcode `0x07` (Tables 1-18/1-20); the first parcel is
`10 | 0x07 << 8 | smode << 4 | dmode` (`11 | ...` for the five-parcel
form).  The destination mode field carries the size: `0x4` is a double
word at a stack offset, `0xC` and `0xD` a quad word at an absolute
address and at a stack offset (p. 3-18).  Source modes `0xC` (absolute
word) and `0xD` (stack-offset word) name the first word of the block.

| address | parcels | instruction |
|---|---|---|

## Pre-state

The fixed pre-state of `README.md`: PC `0x00000000`, PSW `0x00000200`,
SP `0x00000100`, MSP `0x00000180`, memory zero except the image.  The
window is `[0x100, 0x180)`: R16..R52 are in the stack cache, `0x200` and
above are memory.  All block addresses are double- or quad-aligned as
p. 3-18's Notes require.

## Retirement lines

L01. `HRI pc=0000 insn=c7fd1122 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000110 data=11223344 mask=0f trap=0 cyc=5`

Cycles: 5 — Table 4-34 (p. 4-4), `Constant to SC quad-word` = 5.

Transition (p. 3-18): `DQM $0x11223344, R16`, destination mode `0xD` (quad word, in the stack cache): `0x110`, `0x114`, `0x118`, `0x11c` receive the constant.

L02. `HRI pc=000a insn=86fd00aa sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000114 data=000000aa mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Transition (p. 3-32): the block's second word becomes `0xaa`, so that the four words are not all alike.

L03. `HRI pc=0010 insn=86fd00bb sp=00000100>00000100 msp=00000180>00000180 we=1 addr=0000011c data=000000bb mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Transition (p. 3-32): the block's fourth word becomes `0xbb`.  The block is now `11223344, aa, 11223344, bb`.

L04. `HRI pc=0016 insn=87dc0010 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000200 data=11223344 mask=0f trap=0 cyc=6`

Cycles: 6 — Table 4-34 (p. 4-4), `SC/M quad-word to M/SC quad-word` = 4 + D = 6, with the model's D = 2.

Transition (p. 3-18): `DQM R16, *$0x0200` -- a **source in the stack cache**, destination mode `0xC` (quad word, absolute, memory): "moves ... four contiguous words from the source to the destination".  `0x200..0x20c` receive `11223344, aa, 11223344, bb`.  The record carries the lowest-addressed word.

L05. `HRI pc=001c insn=87cc0200 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000220 data=11223344 mask=0f trap=0 cyc=8`

Cycles: 8 — Table 4-34 (p. 4-4), `M quad-word to M quad-word`, printed `8.S`; `S` is not defined on p. 4-2 and is read as a single-word access, the model's S = A = 1 (`sem/hobbit_sem.py` `S_CYC`), so 8.

Transition (p. 3-18): `DQM *$0x0200, *$0x0220`, memory to memory: `0x220..0x22c` receive the same four words.

L06. `HRI pc=0022 insn=87c40208 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000120 data=11223344 mask=0f trap=0 cyc=4`

Cycles: 4 — Table 4-34 (p. 4-4), `SC/M double-word to M/SC double-word` = 2 + D = 4.

Transition (p. 3-18): `DQM *$0x0208, R32`, destination mode `0x4` (double word, stack offset): the two words at `0x208`, `0x20c` (`11223344`, `bb`) go to `0x120`, `0x124`.

L07. `HRI pc=0028 insn=86cd0224 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000104 data=000000aa mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Transition (p. 3-18): the second word of L05's copy, `0x224`, read back from memory: `0xaa`.

L08. `HRI pc=002e insn=86cd022c sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000104 data=000000bb mask=0f trap=0 cyc=1`

Cycles: 1 — `MOV` min=max=1 (Table 4-32, p. 4-3).

Transition (p. 3-18): the fourth word of L05's copy, `0x22c`: `0xbb`.  With L07 this shows that the copy carried each source word to its own place, through two memory-to-memory moves.

L09. `HRI pc=0034 insn=86dd0024 sp=00000100>00000100 msp=00000180>00000180 we=1 addr=00000104 data=000000bb mask=0f trap=0 cyc=1`

## Discriminating check (observed 2026-11-20)

Each bug was injected into the core, `bsv/run_golden.sh 021` re-run, and
the file restored; the clean run after the last one matched all 14 lines.
The reference model matched at once.

| injected bug | lines that failed | what the core did |
|---|---|---|
| the source address not advanced per word | L05 onward | stops after L04: the second pass reads the first word's address again and the run ends there (4 records) |
| the destination address not advanced per word | L05 onward | likewise, 4 records |
| a quad word moved as two words | L06, L08, L09 | L06 `data=00000000` (the third word of L04's block never reached `0x208`), L08 and L09 zero |
| the later words also retire a record | L05 onward | three extra records after L04: `addr=00000204 data=000000aa`, `00000208`, `0000020c`, each with the instruction's `cyc=6` |
| a block source refused by the decoder (the state before) | L04 onward | L04 is the trap record (`trap=1`, `*(SP) = 0x16`) |
| Table 4-34's row not chosen by where the blocks live | L04 | `cyc=8` for `cyc=6` |
