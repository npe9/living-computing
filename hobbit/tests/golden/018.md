# Golden 018 — a mispredicted branch squashes the wrong-path instruction, warm

Table 4-35 (printed p. 4-5) prices a conditional jump that is predicted
wrongly right after its compare at 3: the jump's own slot and the two
slots behind it, which hold instructions from the predicted path and are
thrown away.  This trace fixes the *throwing away*.  It is a two-pass loop
whose first branch is predicted not taken and is taken on both passes, so
the instruction after it, `MOV $0xdead, R12` at `0x000e`, is on the wrong
path both times and must never retire.

The first pass cannot tell a model that squashes from one that does not:
the wrong-path instruction has never been decoded, and the redirect
arrives before its decode finishes.  The second pass can: the instruction
was decoded on the first pass (and squashed), so it is available at once.
Until 2026-11-20 the Bluespec core retired it on the second pass -- found
by 1st Edition Plan 9's `echo` at its 48th retirement (`atexit`'s table
scan), not by any earlier golden, because no earlier golden runs a
mispredicted branch twice.

The image is 9 words = 36 bytes; 12 records retire (the loop body twice).

## How this file was derived

By hand from the printed tables, before either model ran it.  Neither
`asm/` nor `sem/` nor `bsv/` produced or corrected any field.

## Retirement lines

A folded branch is its own record (p. 4-3 note; `sem/README.md`), after
its host's.  No SP/MSP changes occur.

L03. `HRI pc=000c insn=10040000 sp=00000100>00000100 msp=00000180>00000180 we=0 addr=00000000 data=00000000 mask=00 trap=0 cyc=3`

## Discriminating check (observed 2026-11-20)

The fix is one line in the core's `redirect` rule (`if (s3.squash)
s2.flush;`).  With it removed, `bsv/run_golden.sh 018` printed 99,989
records where this trace has 12: L01..L08 as here, then the wrong-path
instruction retiring as an extra record after L08 (`pc=000e
insn=86fddead`), and the loop never terminating (the run ends at the
harness's clock limit).  The first pass, L01..L06, is identical with and
without the fix, as the introduction says it must be.  With the line
restored all 12 match.

On the reference model the image matched at once; it has no pipeline to
squash.
