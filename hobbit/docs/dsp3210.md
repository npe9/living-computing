# The Hobbit BeBox's DSP3210s: documents, code, emulator

The Hobbit BeBox has three AT&T WE DSP3210s (`bebox_hardware.md` §13).
This file records:

- the manual that describes them;
- the DSP code Be shipped for them on the Nov 1994 disk;
- what that code touches;
- the interface by which `tools/beboot.py` runs them on `tools/dsp3210.py`.

**Decision (owner, 2026-11-24): emulate them.** That is option (a) in
"Options" below.

The tools:

- `tools/dsp3210dis.py`, a disassembler and VCOS module reader;
- `tools/dsp3210.py`, the instruction-set emulator;
- `tests/test_dsp3210.py`.

Page numbers like "p. 4-31" are the ones printed in the manual.
`dsp3210/MANIFEST.md` maps them to scan pages. A statement not backed by
a page or a binary is marked **inferred**.

## Interface with beboot (agreed through the lead, 2026-11-24)

This adopts the board-side interface that the BeBox agent proposed,
unchanged. It is implemented by `class Dsp3210` at the end of
`tools/dsp3210.py`.

**Construction.** beboot builds `Dsp3210(n, bus)`, which starts held in
reset. `bus` provides:

- `read(addr, size) -> int`. `addr` is a DSP bus address, `size` is 1, 2
  or 4 bytes, and values are big-endian (B/LN = 1).
- `write(addr, value, size)`.
- `pins(name, level)`, for every output pin the DSP drives. Today these
  are `bio0`..`bio7`, called on each change of a BIO output (Table 10-13).
  An unknown pin should stop beboot loudly.

**Address window.** beboot maps DSP `0x60000000 + x` to Hobbit RAM
`0x08000000 + x`, up to 2 MB, and stops loudly on any other address.

- The 2 MB window is the BeBox agent's reading of the kernel.
- That the DSP sees the boot block at 0x60000000 is the manual's
  (Appendix A, p. A-2).
- That the host writes it at physical 0x08000000 is from the kernel.
- The alias between the two is **inferred** from those two facts.

The DSP's on-chip memory is modelled inside the emulator and never
reaches the bus:

- boot ROM and MMIO at 0x0 / 0x400;
- RAM1 and RAM0 at 0xE000 / 0xF000.

These sit at 0x50030000 instead when C/PN = 0 (Figure 3-4, p. 3-10).

**Calls.**

| Call | Effect |
|---|---|
| `.release()` | Rising edge of the reset bit (0x10/0x20/0x40 at 0x80001B and 0x80001F). It latches pcw[10..13] from BIO[7..4] and runs the boot ROM (below). The pins are taken as all high, giving pcw 0x3d80 as in Be's vcos.cfg `Boot= 0x3d80`. That the board straps them so is **inferred** from that file. |
| `.hold()` | Back into reset. On-chip RAM keeps its contents. |
| `.set_interrupt(level, pin=1)` | The host's interrupt line into the DSP, as a level that is not cleared automatically. It defaults to IREQ1 because the boot ROM's BRC = 0 path starts on IREQ1 (p. A-4). That the BeBox wires the host's line there is **inferred**. Be's BRC = 1 boot does not use it. |
| `.step() -> 4` | One instruction cycle, which is 4 CKI (§1.3, Figure 1-3). It also counts while in reset or in `waiti`. |
| `.pc` | The next fetch address. |
| `.idle` | True when nothing can change until the board acts: the DSP is in reset, or in `waiti` with the timer stopped and no enabled interrupt latched. beboot may skip time while it is true. |

The object pickles whenever `bus` does (`test_wrapper`).

**Open: the DSP→Hobbit interrupt (bits 0/1 of 0x80001F).** It is not
found yet. The DSP has three kinds of output that could carry it:

- **The bus.**
- **BIO7..0** (Table 10-13).
- **IACK0/IACK1** (p. 5-3). These say which external interrupt the DSP
  is servicing. If an emr bit selects it, they show the processor level
  instead: base, interrupt, error or double error (emr, p. 10-7).

What the code shows:

- The VCOS kernel (`mml/os`) never writes BIO or `emr`.
- `mml/schedule` sets only emr bit 9 (the timer), with tcon 3.
- Only Be's `audio` and `daa` write BIO, for the codec and the phone
  relays.
- Modules reach host services through loader-relocated symbols (e.g.
  `_c_Signal`), not through constant addresses.

Nothing yet points to a pin, so the signal is most likely a bus write
that the board decodes. That is **inferred**, and the write need not fall
inside the RAM window.

Proposal: when beboot stops loudly on an out-of-window access, it should
print the address, size and value. The first run of a DSP client will
then show which address it is. A pin route would show up instead as an
unknown-pin stop. The IACK pins are not reported yet; they will be added
as `pins("iack0"/"iack1")` if the run points there.

**Throughput.** The emulator runs about 104,000 instructions per second
(CPython, one core, a do-loop MAC kernel, measured 2026-11-24). A real
DSP3210 at 50 MHz runs 12.5 MIPS.

- At beboot's 2 DSP clocks per Hobbit cycle, one DSP needs one
  instruction per two Hobbit cycles.
- Idle DSPs cost one call per step until beboot uses `.idle` to skip.
- The audio path needs the timer and serial port modelled in time
  (below). Its speed is a measured question once it runs, not assumed.

## The DSP code on the disk

On the Nov 1994 disk (`bebox/MANIFEST.md`), the DSP code lives in
`/system/vcos`. It is AT&T's **VCOS** ("Visible Caching Operating
System") plus Be's modules. The pieces:

- `vcos.ini`: `MaxDsps=3`.
- `vcos.cfg`:
  - `DspType 3210_F12`;
  - `DspClock 50000000`;
  - `Boot= 0x3d80 HostMem onchipDSP1 1`;
  - on-chip memory 0xE000, 8192 bytes;
  - 10 ms frames.
- `mml/`: AT&T's multimedia library.
- `be.oem/`: Be's drivers.

The host side is `/system/vcas_server`, a Hobbit ELF.

**Recognising it.** The modules are COFF-like files:

- a 20-byte file header;
- 40-byte section headers;
- a 0x38-byte `__ModH` module header;
- in every section, a 0x20-byte VCOS section header whose type is
  sPROG 0x100, sAIAO 1, sFIFO 2 or sPARAM 3.

The first header word varies; 0x0166 is usual, and 0x6601 marks the one
little-endian file, `vsrc1t2x`. Twenty modules ship with their `.s`
source, and the disassembler reproduces those sources:

- `tnop` and `vftax` match word for word (`test_tnop_module`,
  `test_vftax_module`).
- `throttle`'s binary is a different version from `throttle.s`.

Code is position-independent. The loader fills placeholder pairs of the
form `rN = (ushort24) 0; rN <<| 0` with relocated addresses.

**Inventory.** Sizes are in instruction words from `dsp3210dis.py`. Words
that decode as reserved are filter tables, buffers and jump tables in
data sections.

| Module | Words | What it is (from section names, sources, and the code) |
|---|---|---|
| `mml/os` | 491 | The VCOS kernel. `__boot`: sets r22 to the vector table, the stack, dauc, and the timer (tcon 0x2e then 0x2f, timer -1). It copies a kernel image on-chip with `doblock`, writes pcw from a loader-filled constant, then enters `__vcos`, a small execution-list dispatcher. Its 16 interrupt vectors all go through one table of handler pointers that the loader fills. |
| `mml/os_doblock`, `os_nodoblock` | 491, 472 | Variants of the same kernel with and without `doblock` copies. |
| `be.oem/audio` | 720 | Be's audio driver. Sections `_c_mspkr/_c_pspkr/_c_mmic/_c_pmic/_c_wdma/_c_init`. It drives the DSP's own serial port (ibuf 0x404, obuf 0x408, ioc 0x40c, `obf`/`ibe` polling) and its DMA (0x420-0x433). That port carries the AD1849 codec, on DSP 3 (`AUDIO_DSP_ID` 3 in Be's driver header). It also uses BIO (0x41b/0x41e) for codec control. |
| `be.oem/daa` | 937 | The phone line interface: relays and hook via BIO (15 writes to 0x41e), plus the serial port and DMA as in `audio`, and the timer. It writes debug values to 0x60000050/54 in host memory. |
| `mml/schedule` | 2418 | Task scheduling. Uses `emr` and the timer. |
| `mml/modem` | 45561 | Modem data pump. The V.42/LAPM/MNP layers run on the Hobbit, in vcas_server. |
| `mml/g711*`, `g728*` | ~200; 1476-2425 | Telephone speech codecs. |
| `mml/jpegd*`, `ml2e` | 5988; 22666 | JPEG decode, and an encoder. |
| `mml/src*`, `vsrc*` | small | Sample-rate converters (`.s` sources present). |
| `mml/dtmf*`, `cid`, `cngd` | small | Touch-tone generate and receive, caller ID, CNG tone detect. |

**Devices the DSPs touch.**

- Each DSP's own on-chip peripherals (Figure 3-5, Table 10-13):
  - the serial port: the AD1849 codec, DSP 3;
  - DMA for the serial port;
  - the timer;
  - BIO pins: codec control and DAA relays.
- Host memory, through the 0x60000000 window.

No module stores to a constant address outside on-chip memory and that
window. `0xc000` and `0xa000` appear, but as a mask and a data table, not
as device addresses.

**The undocumented operand.** The DA operand field p = 1111 (e.g.
Y = 1111000) is "Not allowed" in Table 10-3. Even so, it occurs about 20
times in AT&T's code. The emulator raises `DspError` on it, so a run will
show whether it is ever reached.

## The boot, both sides

**The host (vcas_server, the BeBox agent's reading).**

1. `vcArmDsp` writes `_vcLoad`'s DSP address as 4 bytes, MSB first, one
   byte per word, at DSP 0x60000000 (`veDspWrMem`).
2. `veDspStart` sets the DSP's bit in `_dsp_control_bits` (0x10/0x20/0x40)
   at 0x80001B and 0x80001F.

**The DSP (Appendix A, pp. A-1..A-4).**

- With pcw BRC = 1, the boot ROM:
  1. reads 8 header bytes from the low bytes of the words at 0x60000000:
     address (bytes 0-3), then count (bytes 4-7);
  2. copies count bytes from 0x60000020 on;
  3. branches to the address.

  The listing, not Table A-1, sets the header order. Be's block has
  count = 0, so the DSP starts executing in host memory at `_vcLoad`.
- With BRC = 0, the boot ROM:
  1. sets r22 = 0x50030000 and emr = 0x8000;
  2. clears C/PN;
  3. executes `waiti`.

  Then IREQ1 vectors to code that jumps through location 0 and clears it.

Both paths are modelled behaviourally, since the ROM is mask ROM with no
dump. Interrupt vectors are r22 + 8n with emr bit n enabling them
(Table 10-7):

| n | Source |
|---|---|
| 8 | EXT0 |
| 9 | timer |
| 11 / 12 | SIO in / out |
| 13 / 14 | DMA in / out |
| 15 | EXT1 |

## VCOS's boot, standing alone

`test_os_boot_standalone` runs `mml/os` from the disk through Be's boot
path. The setup is a boot block holding `__boot`'s address, then the
BRC = 1 ROM path into the module in host memory. Over 176 instructions,
`__boot` does the following:

- points r22 at its vector table;
- sets dauc;
- starts the timer (tcon 0x2e, timer -1, tcon 0x2f);
- copies a 7-word stub on-chip and calls it to write pcw (0x3d80);
- copies `__vcos` on-chip at 0xE000 with `doblock`;
- returns into it at 0xE108.

The run stops loudly at `__vcos`'s fourth instruction. That instruction
loads through the execution-list pointer, which the host has not set
(0), and so reads the boot ROM.

The module's relocations are plain 10-byte COFF entries:
- type 44 is a 32-bit word;
- type 46 is the 24-bit immediate of `rN = (ushort24) A`;
- type 47 is the N of the `rN <<| N` that follows it.

These meanings are **inferred** from the code they land on.

The symbol values are **inferred** too. The module's symbol table is
absent: symptr 0x382b points past the end of the file. So the test
supplies values that are self-consistent: symbols 63/68 place `__vcos` at
0xE000, symbol 12 is the module base, and symbol 81 sets the stack to
0xE400. It also writes the pcw word that the loader would fill, using
vcos.cfg's `Boot=` value.

Six relocations stay unresolved: five external symbols of `__vcos` and
one of `__ModH`. Those are host-side structures. Resolving them is
vcas_server's loader's job, and the real values will come from beboot's
run.

This run found one bug, now fixed. SHIFT-OR (`rD = rS <<| N`, p. 4-75)
ORs N << 16 with all of rS; the model had kept only rS's low half.

## What the emulator models

The full list is in the `tools/dsp3210.py` docstring.

**Implemented**, each with a manual page:

- **Registers.** All CA registers (Table 10-2); the pc reads as the
  address + 8.
- **Branches.** Delayed: the next instruction runs before the target.
  `ireturn` has no delay. `nop` is 0x80000000, and `return` is
  `goto rM` (section 4.6).
- **Loops.** `do`/`doblock`/`dolock`, with B = bit 24 and M = bit 23
  (p. 4-31).
- **CA arithmetic.** 16- and 32-bit, with flags (Table 4-1).
- **Loads and stores.** In all widths, with post-modification (7a-7d).
  `sp` always steps by 4.
- **The memory map**, selected by C/PN.
- **The boot ROM**, both paths.
- **Interrupts**, with shadow registers; `waiti`.
- **The timer**, at CKI/2 or CKI/4.
- **The DAU.** DSP32 floating point: N = M x 2^(e-128), M = (-2)^s + 0.f,
  and e = 0 means zero (p. 3-8). It covers MAC formats 1-4, the format 5
  special functions, and the IEEE conversions (8.2.4.1).
- **The 4.4.2 latencies.**
  - A DA memory write is visible 4 instructions later.
  - An accumulator used as a multiplier input is the value of 3
    instructions earlier.
  - A DAU condition uses the flags of 4 instructions earlier.

**Not yet modelled.** Each of these fails loudly where it is reachable:

- serial port bit timing;
- DMA;
- mu-law/A-law `ic`/`oc`;
- `seed`;
- the 40-bit accumulator's guard-bit rounding (8.2.3);
- error exceptions other than illegal opcode.

The SIO and DMA registers are plain storage for now. The next work
for audio is to model the serial port and DMA in time, with an AD1849 at
the other end.

## Options considered

The owner chose (a). The other two are kept for the record.

| Option | Evidence | Size |
|---|---|---|
| **(a) Emulate the ISA and run AT&T's real VCOS and Be's modules** | The manual is complete. The ISA is small: about 15 CA formats and 5 DA formats. Every instruction in `os`, `audio` and `daa` decodes, except data and the p = 1111 operand. The fidelity goal favours running the real code. | The core is done: ~1,000 lines, 28 tests. Still to come: SIO+DMA in time, an AD1849 model, and beboot wiring. |
| (b) A behavioural stand-in for VCOS on the host side | It would have to reverse-engineer and imitate VCOS's undocumented host protocol: execution lists, FIFOs, parameters. It would replace AT&T's kernel with our own. | Unknown, and it grows with each client. |
| (c) Inert DSPs | The boot reaches the Terminal shell without them: the host waits for nothing (BeBox agent). DSP clients (`/apps/sound`, Phone, `vcRead*` FIFOs) would hang or fail. | Zero. It is the fallback while (a) is wired in. |

## Tests

`tests/test_dsp3210.py`, run by `tests/run_tests.sh`. It covers:

- **Decoder:** the manual's own encoded examples (section 4.6), I/O
  condition branches, the do forms, reserved encodings.
- **Modules:** `tnop`, `vftax` and the `os` boot mover, read from the
  disk image, and the standalone VCOS boot above. Set
  `HOBBIT_9308000058` to the image path, or these four tests skip.
- **Float and IEEE conversions.**
- **The model:** one program for each pipeline-visible rule; the BRC = 1
  boot block, standing alone; the timer interrupt through `waiti` and
  `ireturn`.
- **The beboot wrapper,** including a pickle round trip.

Each injected bug, and the failures it produced, is in the test file's
header.
