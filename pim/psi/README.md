# pim/psi: the PSI side, starting with the Librarian's loader

This directory is the PSI software side of the SIMPOS reconstruction.
It is reference software in Python and needs no hardware. Its plan is
`../docs/simpos/README.md` §4-§5. The first piece is step 1 of the
adopted route (`../docs/simpos/layers/OPTIONS.md`): **the Librarian's
loader**, which turns package templates (`.ptf`) into class objects.

**Everything here is OURS.** SIMPOS's own loader is lost. Each rule the
code applies is labelled SOURCED (with the printed source and page),
MEASURED (on the held files, with the probe named) or OURS (a choice
made here). The labels are repeated in the docstring of `librarian.py`.

## How to run

From `pim/`:

    python3 -I psi/test_librarian.py              # the tests (~10 s)
    python3 -I psi/librarian.py report            # per-package results
    python3 -I psi/librarian.py free              # the "102 classes" check
    python3 -I psi/librarian.py class paragraph##time_graph_window [--listing]
    python3 -I psi/librarian.py report --after forward   # the thesis's after-demon order
    python3 -I psi/plaintext.py --tsv psi/plaintext_disagreements.tsv
    python3 -I psi/test_kl0.py                    # the interpreter's tests (~2 s)
    python3 -I psi/kl0.py convert                 # convert/3 against pimos.vmac
    python3 -I psi/kl0.py census [--tsv FILE]     # every method of the 104 classes
    python3 -I psi/kl0.py census --fep [--tsv FILE]   # every method of pimfep and pimscsi, stand-ins loaded
    python3 -I psi/kl0.py census --fep --recipes      # the same, receivers made by their held creators
    python3 -I psi/kl0.py call paragraph##paragraph_version get_version/2 _
    python3 -I psi/test_espc.py                   # the compiler's tests (~8 s)
    python3 -I psi/espc.py check paragraph kappa2 utter [--tsv FILE]
    python3 -I psi/espc.py behave [-v]            # compiled paragraph against paragraph.ptf
    python3 -I psi/espc.py compile psi/standin/stream.esp --package simpos --listing

None of these needs an extraction: `held.py` decompresses the archives
in memory. To work from files instead, run
`python3 -I psi/held.py extract DIR` (DIR must be new or empty; 1,048
files in under a second) and pass `--held DIR`. Nothing from an archive
is executed. Members with absolute or `..` paths, and non-regular
members, are refused.

## What the loader builds

**Templates** (MEASURED on all 1,455 classes, no failures). The class
trailer is 13 terms anchored on the atoms `<class id>, template`:

1. the id and `template`;
2. two stamps;
3. the class-predicate code references;
4. the class slots as (name, flag, init) triples;
5. the instance-predicate code references;
6. the instance slots;
7. the local-predicate offsets;
8. a dynamic-predicate field;
9. the natures;
10. the referenced classes;
11. their union.

What was measured about these fields:

- **Code references.** Each one names the predicate whose header
  `(atom, kind<<8|arity, predh, 0)` points at that offset. Every
  reference resolves, and no header is left unreferenced.
- **Cell numbering (settled 2026-11-24).** A hash table spans
  `mask+1 + 2*keys + 2` cells (`ptfdump.table_span`), not its size
  word + 1 as ptfdump counted before.
  - The test: renumber every cell of the eleven packages with that span
    and count the headers whose head (predh) cell is not at offset - 2.
    Result: **0 of 32,901**. With the size word, 3,662 heads in 91
    classes were displaced.
  - Every local call (pmi `60`/`61`/`62`, target cell + 2 + signed 16
    bits) lands on a predicate's code: 35,542 of 35,542 (pinned by
    `test_cell_numbering`; with the old span that test fails).
  - Every class's code now ends exactly at `L` (554 of 554 in the six
    psdpim/paragraph packages; `ptfdump.py --check`, pins updated).
  - The size word is not a size. It is the miss offset: a key that is not
    found goes to cell + 2 + the word (`psi/fepread/ptfread.py`). In
    149 of 212 tables that is the cell after the table, where the word
    equals `mask + 2*keys + 1`. In 53 of the other 63 it is an
    instruction of the same predicate, such as a catch-all clause. In 10
    it is a cell tagged 0x96, which is UNKNOWN; `kl0.py` would refuse
    there. This is an ad hoc count over the eleven packages,
    2026-11-24.
  - The loader still finds each predicate by its header and renumbers
    from the header's offset; that is now the identity.
- **Term tags.** The trailer's term tags confirm more of the tag pairing
  in `layers/KL0.md` §2: list 2, strg 3, flt 10, svct 23, hvct 24 and
  mod 27, with code references as loc/cod plus a GC bit.
- **Slot flags.** 0x10 marks an attribute. Without it the slot is a
  component, and its name is `pkg##class$slot`, the renaming TM-388 §3.5
  describes. 0x02 means the initial value comes from the slot-init
  predicate (kind 0x22 or 0x32) at the code reference. 0x01 marks
  `slot is Class`. All three are witnessed against source (below). A
  slot declared without a value compiles to the constant 0.
  `slot := #Class` compiles to an init predicate, and `#"c"` compiles to
  a constant.
- **Header kinds.** All of them are witnessed by source: 0x25/0x35
  primary, 0x26/0x36 before-demon, 0x27/0x37 after-demon, 0x22/0x32
  slot initialisation, 0x11 local, 0x12 `$or$N`. Kind 0x26, a class
  before-demon, occurs once, in kappa. Kind 0x37 is matched to source
  119 times in kappa (ad hoc count over plaintext.py's matches, 2026-11-23).
- **The dynamic-predicate field.** It is 0 in every class but one,
  `tour##tt_belief_system`. There it is 19 pairs of (local offset, flag),
  and the source declares 19 `:- dynamic(P/N);`. What the flag means is
  UNKNOWN.

**Linearisation** (SOURCED: TM-388 §3.2 p.39). The order is depth-first
and the first occurrence wins. The class itself goes where `*` is, and
first if `*` is omitted. Loops are refused.

- Every held nature vector is fully qualified. The `.ptf` files contain
  no unqualified nature.
- One class writes `*` in the middle: `pimmcsp##csp_write_messages`
  (`_before, *, _after, ...`).
- A nature that is not loaded stays in the order as an opaque node, and
  the class is marked **partial**, because what that node inherits is
  unknown. Every unloaded nature in the held packages is a `simpos##`
  class.
- The implicit root, class `class` (TM-388 §3.6), is a flag on the
  class object and not a node in the order.

**Method combination** (SOURCED: TM-388 §3.4 pp.42-43). The before-demons
run in inheritance order. The primaries are tried as alternatives in
inheritance order. Then come the after-demons. Class methods and
instance methods combine separately, and locals are not inherited.

**Slots** (SOURCED: TM-388 §3.5). Attributes with the same name collapse
into one slot, and the first initial value in inheritance order wins.
Components stay distinct. OURS: slot numbers follow the order of first
appearance.

**Method and slot tables** (SOURCED in structure: Nakashima's thesis
App. A, Fig. A-1 p.241 and p.242).

- Each table has an index of 2^N entries, each a (base of synonyms,
  number of synonyms) pair, and a contents part in which a key's
  synonyms are contiguous.
- The hash is the key's low N bits.
- The method key is `k = n*2^24 + a + n`, and the slot key is the
  name's atom number.
- OURS: the table size (the smallest power of two that holds the keys),
  the atom numbers (interned in load order, 28,399 atoms), counting the
  receiver in `n` (the template's arity does), and the layout in words.
  With these choices the longest synonym chain is 6 (ad hoc probe over all class objects, 2026-11-23). The thesis reports
  1-2 for its own sizes, so its sizing rule is not ours.
- `Librarian.send` looks up a selector through the table.

**Method bodies** stay KL0. Each predicate keeps its cells as ptfdump
decodes them, for the KL0 interpreter of step 2.

## The after-demon order: a switch

`Librarian(after_order=...)`, or `--after` on the command line:

- **`'reverse'`, the default.** TM-388 p.42 says "what is first
  inherited is executed last". Its worked example on p.43 is
  `b1,b2,b3,(p1;p2;p3;fail),a3,a2,a1`. TR-044 p.20 agrees.
- **`'forward'`.** The thesis, p.243, prints `m :- b0..bn, p, a0..an`.

The TM-388 page images (PDF pp.54-55) were read for this.
`layers/ESP.md` §5 reported a conflict inside TM-388, but there is none:
the "in the order of the inheritance" sentence describes the AND
operation, and the next paragraph states the order explicitly. The
conflict is TM-388 and TR-044 against the thesis. In the held code it
matters for 11 combined methods, those with two or more after-demons (ad hoc count over `build_all()`, 2026-11-23).

## The KL0 interpreter (step 2, 2026-11-24)

`kl0.py` runs the method bodies of the loaded classes. It is OURS: the
PSI's KL0 firmware is lost, and nothing here emulates it. It is a
WAM-shaped machine (`../docs/simpos/layers/KL0.md` §3) whose
instruction set is exactly the rows of `kl0_opcodes.tsv`.

**Opcodes are named only from known plaintext.** Each of the 132 rows
(100 at step 2, nine more at step 3c, four at step 3d, twelve at step 3e,
seven at step 3g)
cites a predicate whose compiled cells sit next to the held ESP clause
they came from (`pkg##class pred/arity @cell`, source file, clause).
An opcode without a row is refused loudly (`Refusal`, cause
`opcode`). So is an operand pattern the witnesses never showed, such
as a 16-bit immediate with its top bit set, or a three-register
built-in whose result register is not its first operand (where no
witness shows it). The rows are
77 class-0 (`pmi`), 44 class-1 (`blt`) built-ins, 3 atom-cell forms
and 1 hash table (`cd00`). A few class-0 rows are opcodes whose
difference from a sibling is UNKNOWN (e.g. `24` beside `20`, `de`
beside `dd`). They execute alike, and their rows say so.

`fepread/witness.py`, written separately for `docs/fep_services.md`
§6, witnesses 40 readings. Where its rows and these overlap, they
agree, and 44 rows here cite it as an independent witness. Five rows
come from it: `pmi 37` (get_vector of n), and blt `25` (class object),
`62`/`64` (==) and `65` (\==). Its count of hash tables (0 misses over
142) agrees with the cell numbering above. Its finding that a `0308`
string's count is in bytes, not words, is now applied in
`librarian._term`.

**The string rows** (2026-11-24): blt `0b` string/3 (S, ^L, ^T),
`1c` new_string/3 (^S, L, T), `23` string_element/3 (S, I, ^E) and `2b`
set_string_element/3 (S, I, E), from paragraph's `time_graph_window`,
`g_dev`, `history_manipulator` and `view_select_menu`. new_string's
witnesses include S != T (`view_select_menu change/3`: `1c 04 00 01`,
the string out in A4), which settles which operand is the output. The
elements of a new string are 0 and their type is what T says (OURS:
neither is witnessed beyond the type). kl0's string object keeps its
type. In the six-package census, two methods get further:
`csp_default_write write/2` stops at `string/3` on an unbound argument,
and `state_pe reflesh/3` at a `draw_string/6` sent to an unbound
receiver.

**`:refute(Object, Method, Args)`** (TM-388 p.46, PDF p.58: class
`class`'s dynamic call) is modelled (OURS): the vector's elements become
the arguments after the receiver, and the method is sent to Object. It
is the second class-`class` method kl0 runs, after `new/2`.

MEASURED facts the witnesses settled:

- A predicate finds its entry cut barrier in register A_arity.
  kappa##kappaDBC_interface `pic/1` keeps A1 with `20 01 00`, cuts to
  it with `dd 01 01` and, after a call, reloads it from Y0 and cuts
  with `de 01 01`. Over the eleven packages:
  - in 1,464 of 1,464 `dd A n`, A is the predicate's arity and n the
    preceding allocate's size;
  - in 4,255 of 4,255 `de A n`, n is that size, and A is the arity in
    4,254.
- `blt 66 A B` succeeds if A_A < A_B, and `blt 67 A B` if A_A >= A_B.
  So `Y =< H/2` compiles to `67 H Y`.
- A hash table's entry target is the stored offset + 1.

OURS: a disjunction `$or$N` (header kind 0x12) keeps its caller's
barrier, so its `!` (d0) cuts the whole clause. This agrees with
`pic/1`'s `$or$3/1`, whose `!` is d0 with A1 already overwritten, but
no test discriminates it.

**Method dispatch** goes through `Librarian.send` and runs TM-388
§3.4's combined method: before-demons, then the primaries as
alternatives, then after-demons. Class `class`'s `new/2` is OURS. It
builds an instance whose slots take their constant initial values. The
loader's `Slot.term` keeps a constant's pool tag, so a string initial
value stays a string (`paragraph_version` answers `string#"3500"`).

**Slots initialised by code** (2026-11-24). `new/2` runs them.

- The calling convention is MEASURED. All 424 slot-initialisation
  predicates of the eleven packages (kind 0x22: 33, kind 0x32: 391)
  have arity 1 and no receiver argument, and the value comes back in
  A0. The witness is `paragraph##time_graph_window display_pos/1`,
  compiled from p_tgraph.esp `(display_pos:=L :- :create(#list_index,L))`:
  `a9 01 ..` puts the class into A1, then `blt 25` and `pmi 74 01 02`
  send `create/2` with L still in A0. `espc.py` compiles this
  predicate cell for cell.
- The semantics are SOURCED from TM-388 §3.5, pp.49-50 (PDF pp.61-62,
  page images read).
  - An instance slot's value is computed when `new` makes the instance.
    A class slot's value is computed "when the class is generated".
  - If the predicate fails, `new` fails, or the class is not generated.
  - The order "is uncertain".
  - The predicate cannot use the object being made.
  - A slot may not hold an unbound variable (p.48).
  - `slot is Class` stores "an instance object for the class" (p.49,
    (3)). kl0 used to store the class object. It now makes the instance
    with `new/2`. Only kappa has such slots (102).
- OURS choices:
  - Each predicate runs on its own sub-machine, to its first solution.
    The sub-machine shares the code and the class slots.
  - The slots are filled in template order (the held templates list them
    in reverse source order).
  - Class slots are computed at the class's first class-slot access,
    standing in for load time.
  - An unbound value refuses (`slot init unbound`). A failing class-slot
    predicate refuses (`class not generated`).
- Tests are in `test_kl0.py` on kappa alone, against its source.
  - `kappaMDM_hash_table`'s `new_heap_vector(Table,128)` gives 128
    zeros.
  - `kappaMDM_access_right` makes two distinct hash tables, each with its
    own vector (a nested initialiser), and `faot` is
    `@max_faot_entry+1` = 21 long.
  - `kappaTBO_SDB_RUC_control`'s two-goal initialiser gives
    `{1,0,...}` of 21.
  - `kappaHLC_selection`'s `is` slots are instances, one with its own
    `is` slot.
  - `test_espc.py` checks the failure, unbound, class-slot and
    after-demon cases on compiled classes.
- No new opcode was needed. Of the 424 held predicates, 308 use only
  opcodes in the table. The other 116 use opcodes with no row: blt 1c
  (84), blt 3e (31), blt 35 (2), blt 54 and blt 2b (1 each). This is an
  ad hoc count, 2026-11-24.

**Results** (pinned in `test_kl0.py`):

- `pimfep##fep_command_code_table:convert/3`, run both ways, against
  the 104 `fep#name => code` macros of PIMOS's `pimos.vmac`:

## The ESP compiler (step 3, 2026-11-24)

`espc.py` is OURS; ICOT's compiler is lost. It parses with the census
reader (`../asm/simpos_census/esplex.py`) and emits a `Template`, in the
form the loader builds, carrying its own constant pool. The code-shape
rules are in its docstring: registers, permanent variables, clause
chains and cut operands, each measured on the held code.

**What it may emit.** Only opcodes with a row in `kl0_opcodes.tsv`.
Anything else is refused as `CompileRefusal(construct, detail)`, and a
predicate that calls a refused local is refused with it. The largest
refusals over paragraph are: calls a refused local (215), `X+Y` on two
registers (157), `heap_vector/2` (101), `X/Y` (41), the
`double_bytes#` macro (37), a head term (35) and `=\=` (34). Over kappa2,
all 739 classes with source compile now that `with_macro` is expanded
(below); before, 404 were refused whole for it.

**Macro banks (`with_macro`, TM-388 §3.7.3 pp.72-75, page images).** A
class `with_macro B` has its clauses rewritten by bank B's clause-level
rules, `Pattern => Expansion`, before compilation: head arguments, body
goals and their arguments, top-down, the result expanded again. A bank
inherits its `nature` banks' rules; its own are tried first
(INFERENCE: TM-388 states the inheritance, not the order).
`esp_macro_expander`, which every bank inherits, is SIMPOS and not
held; its standard macros are the compiler's own. Not modelled, and
refused by name as `macro rule` for the predicate that meets one: a
rule with a `when`/`where`/`with`/`by`/`:-` tail (15 in kappa2's
banks), `==>` (one), and a backquote. Measured over kappa2's banks:
about 3,811 rules, nearly all `@name => constant`. A bank whose source
is not held refuses the class as `with_macro` (utter: `cil_macro`,
`travel_fts_macro`, 10 classes). The structural witness: of kappa2's
1,323 exact predicates (measured when `with_macro` landed, before the
string built-ins), 822 are in the 406 classes with a bank, and 109
have source clauses a bank rule changed, so the expansion meets
`kappa.ptf` cell for cell.

**Structure** (`espc.py check`, against the held `.ptf`). Each class is
checked for natures, slots with their flags, the declared method and
local sets (refused ones included) and the demon set. Each predicate
pairs compiled cells with held cells in a position-independent form.
A disjunction is paired by where it is called from (`parent#k`), not by
its `$or$N`. The held numbering does not follow source order: in
`paragraph##receiver`, `send/7`'s disjunctions are numbered before
`draw_graph/6`'s, although the source has them after.
