# tm115: SIMPOS as seen by the PSI Font Editor (TM-115, TM-112; Touati, May 1985)

Sources:
- TM-115 "PSI Font Editor Implementation Notes", 119 PDF pages, `lit/trtm/tm0115.pdf`. Printed folio =
  PDF page - 5 in the body (e.g. p13 = printed 8, page "2-6").
- TM-112 "PSI Font Editor User Guide", 25 PDF pages, `lit/trtm/tm0112.pdf`. Printed folio = PDF page - 4
  in the body.

Version: both describe SIMPOS **Version 1.00**. The screenshots' status line reads "SIMPOS Version 1.00",
dated 23-May-85 (TM-115 p25, p26; TM-112 p25, SCREENSHOT). The editor was cross-compiled on the DEC-20
(TM-112 p7).

**What kind of document this is.** TM-115 contains **no ESP source listing**. It is a class-by-class
prose reference: slots, methods with argument lists (prefix `^` = output, unprefixed = input), local
predicates, and bug notes. Every method below is therefore graded PRINTED-INTERFACE (signature printed,
no body) or PROSE. The only printed code fragments are one line each (see work dir `fragments.txt`).

Arity convention: the receiver is counted, as in `required/`. `:m(Obj,A,B)` = m/3; a class method
`:create(Class,^Inst,Name)` = create/3.

Key work-dir files (`.../simposdive/work/tm115/`):
- `fragments.txt`: the eye-checked code, the menus, the boot dialogue and the status line.
- `tm0115_all.txt`, `tm0112_all.txt`: OCR concatenated, with page markers.

What these lists say about each SIMPOS class (PROSE):
- `user_window` is "a basic window class" (TM-115 p40).
- `with_superior_input_buffer`: input made through this window can be read from a superior window
  (TM-115 p40, p42).
- `as_input_buffer`: input made through an inferior window can be read from this window
  (TM-115 p41).
- `as_superior`: (on the superior side) appears with `as_input_buffer` (TM-115 p41).
- `sash`: "provides a frame delimiting the area on the screen used by" the window or menu
  (TM-115 p42).
- `as_temporary_window`: the window disappears "as soon as the mouse is no longer inside" it
  (TM-115 p92).
- `with_label`: provides the slot `title`. The editor's classes do not inherit it, so they define their
  own `title` slot and `:get_title`/`:set_title` (TM-115 p41).

Reading through a superior. All windows and menus of both modes are created with one full-screen
superior window as their superior. The top-level loop reads each input "in a single instruction"
through it, **together with the window or menu it came from** (TM-115 p27, p105). PROSE. The
read method's name and the format of the input pair are not printed.

The selection limitation (PROSE, TM-115 p111; TM-112 p9-10):
- "it is not possible for a program to read an input from a window which is not selected."
- A click in a window that is not selected goes to the window manager. A single left click selects
  the window; anything else is ignored.
- A click in the selected window goes to the program.
- TM-115 p111: "The next release of the window system will allow" reading from an unselected window.

### W3. User methods versus manager methods (POSSIBLE SIMPOS architecture, PROSE)

- In SIMPOS 1.00, processes have no direct access to bitmap memory. "this task has been attributed
  to the window manager" (TM-115 p43). Any method that uses bitmap areas and transfers them to a
  window "must be currently executed inside the window manager".
- The editor confines such methods to two classes, `font_graphics_window` and
  `as_edit_pattern_window` (TM-115 p43, p67).
- Naming convention: a user method `:x` sends a request; the manager-side method is `:do_x`. Examples:
  - `:draw_record`/`:do_draw_record` (TM-115 p44)
  - `:inverse_square`/`:do_inverse_square` (TM-115 p81)
  - `:draw_record(Message)`/`:do_draw_record(Message)` (TM-115 p81)
  - the system pair `:get_size`/`:do_get_size` (TM-115 p82)
- Code running inside the manager must call manager methods ("not user methods", TM-115 p82).
  Code outside it "must send messages to the window manager for executing manager methods"
  (TM-115 p85).
- The mechanism, i.e. how `:draw_record` gets `:do_draw_record` run in the manager process, is
  **not printed**. INFERENCE: a call-through-manager primitive (window-manager RPC). OPEN QUESTION.

### W4. Bitmap / raster operations (PROSE unless noted)

- ALU operation names: `exclusive_or` (the default, used everywhere), `inverse`, `copy` (TM-115 p43,
  slot `operation` of font_graphics_window). PRINTED (atoms).
  - All grid, pattern, box and code drawing is XOR, so redrawing erases (TM-115 p55, p59, p62, p77).
  - Compare TM-125 (STRUCTURE.md section 7): draw_line etc. "with ALU arguments".
- Bitmap **areas** (off-screen bitmaps):
  - "creates a bitmap area, loads the pattern ... in it, copies this area or a part of it in the
    window screen ... and kills the area" (TM-115 p44).
  - Area widths must be multiples of 16 because writing into an area is "only by using double bytes
    buffers or strings" (TM-115 p82).
  - "the window system does not usually clear the areas when allocating them" (TM-115 p79).
  - Verbs used: allocate / create, load (a string), transfer, deallocate / kill. **Method names are
    not printed.**
- `as_general_font` (SIMPOS window-system class, "less than one page long", written "by Iima san",
  TM-115 p16):
  - It holds an inherited slot, the font bitmap area. The slot is `nil` when unused; once used it is
    an area holding all patterns.
  - `:get_attribute(Font,Code,^Font_bitmap_area,^X,^Y,^W,^H,^Bias)` exposes it (TM-115 p17).
  - **So a SIMPOS 1.00 font is an area plus per-code rectangles. INFERENCE: the window system draws a
    character by an area-to-screen transfer of that rectangle.**
- Pattern strings: patterns are stored as double_bytes strings because "the window graphics methods
  accept patterns only if stored in double bytes strings" (TM-115 p11). Bit order (TM-115 p74-76):
  - a word X = X0*2^15 + ... + X15*2^0
  - dot i of a 16-dot run is bit Xi, so the most significant bit is the leftmost dot
  - rows of `raster_width` words, row-major
  - the row is padded with white on the **left** to a multiple of 16
- Grey: one dot in four, each line repeated twice to avoid flicker. Black+grey overlap reads as
  "dark grey" under XOR/add (TM-115 p78).
- Line drawing: `draw_vertical_lines` draws lines of thickness 4 (TM-115 p52). The frame width
  between register boxes is 3 (TM-115 p37). Characters are not drawn within 3 dots of the window
  edge (TM-115 p44).
- Screen size: `screen_width` and `screen_height` are slots. Height differs between Mitsubishi and Oki
  PSI (TM-115 p27). The grid is "more than 600 lines" (TM-115 p110). PROSE.

### W5. Mouse and keyboard event formats (PROSE)

The editor distinguishes these mouse inputs: single left, double left, single middle, double middle,
single right, double right (TM-115 p83, p85, p97-99, p106; TM-112 p10-11, p19). Atom spellings are
**not printed** in these reports. Compare TM-125: `mouse$l`, `mouse$m`, `mouse$r`, `mouse$rr`
(STRUCTURE.md section 7).

| Input | Meaning in the editor | System meaning | Cite |
|---|---|---|---|
| single left in an unselected window | selects the window (window manager) | SYSTEM | TM-112 p10 |
| single left in a selected window | command / draw dot | app | TM-112 p10 |
| double left | cycles brush colour | app | TM-112 p10; TM-115 p86 |
| "it is hard for the system to understand double clicks if you enter a single click just afterwards" (wait 1-2 s) | — | SYSTEM timing | TM-112 p10 |
| single middle | reshape box; abort a 2-point input | app | TM-115 p88; TM-112 p22 |
| double middle | move box; clear all registers | app | TM-115 p88, p103 |
| single right | stops the editor and returns to the debugger (top level succeeds); DRAW: lift/lower pen | app (debug aid) | TM-115 p106; TM-112 p19 |
| **double right** | "displays the system menu"; "Clicking double right will always make the system menu prompt out" | **SYSTEM** | TM-112 p16, p19 |

Mouse position:
- Inputs carry or allow a position (X,Y) "just after the clicking" (TM-115 p53), in the window's
  inside units (TM-115 p80).
- DRAW mode also tests "if the mouse is outside the window" (TM-115 p85).

Keyboard (font_temporary_window, TM-115 p92-94):
- Accepted characters: a-z, A-Z, digits, `_`.
- Carriage return ends input.
- **Control-D** clears and restarts the line.
- **delete code** erases one character.
- Input length is at most 256 double bytes.
- Confirmation: `" (Y/N) "` is appended; "y", "Y" or CR means yes.
- Separators for number lists. TM-112 p22 shows the format `Code_0,Code_1,...,Code_n,`.

Abort conventions: moving the mouse out of a temporary window aborts, because `:read` fails
(TM-115 p86, p93).

### W6. Menus (window-system format)

- Menu item lists are "in the format required by the window system for menus". The editor passes
  `(Class_name, Items_list)` per menu (TM-115 p32, p37). **The item-list format itself is not
  printed.** OPEN.
- "Their size is automatically computed by the window system" when menus are created (TM-115 p25).
  The editor reads the minimum sizes back to lay out the screen (TM-115 p33).
- Menus are multiple-select / multi-column classes. A multi-column menu lays items row-major in N
  columns (SCREENSHOT TM-115 p26).
- "blacken the currently executed command on the display ... This facility is provided by the window
  system" (TM-115 p111). This is menu item highlighting. PROSE.
- `parameters_display_menu`: a menu is used to display three numbers "because menus know by
  themselves how to display ... and the space required ... and windows do not" (TM-115 p63). It is
  faster to create a new menu than to modify an old one.
- Window-manager constraint: "the window manager does not allow a window to go out of the screen".
  The editor therefore moves a window to (0,0) before resizing it (TM-115 p29). PROSE.

### W7. Screen layout and the status line (SCREENSHOT)

**Status line** (TM-115 p25, p26; TM-112 p25):
- Two lines across the bottom of the screen, white on black.
  - Line 1: `USER : me`.
  - Line 2: `SIMPOS Version 1.00`, a reverse-video field, then `23-May-85 Thursday 20:22:44`.
- The reverse-video field shows the **name of the currently selected window** (TM-112 p9).
- That name is the class name (TM-115 p111: "the names of the class of objects to which the menus or
  the windows belong"). A second or third instance of the same class shows as
  `pattern_display_window/2` and `font_multiple_select_menu/3` (TM-112 p18 Appendix A, PRINTED table).
- The field truncates long names: `font_multiple_select_multi_column_` (34 characters shown).
- INFERENCE: default window title = class name + "/N" for the Nth instance.

**Character mode:** 8 windows (TM-112 p9). **Pattern mode:** 9. Total 17 permanent windows. Layouts
are in `fragments.txt` (TM-115 p25-26, p30-35).

The pattern mode uses a temporary full-screen window to hide transitional redraws while resizing
(TM-115 p36).

## Font format and font classes (WINDOW / file system)

### F1. 1985 on-disk font format (PROSE, TM-115 p13-14 eye-read; TM-112 p8, p16)

- A font is two binary files of double_bytes in directory `>sys>user>font`. The slot value is printed
  `">sys>user>font"` and path = Directory ++ Font_name ++ Postfix ++ ".bin" (TM-115 p15). OPEN: the
  `>` separator before the name is not printed.
- `<name>hd.bin`, the head file:
  - Head, 5 words: line_height, base, number_of_char, raster_width, total_height.
  - Body: 6 words per character: code, font_x, font_y, width, height, bias.
- `<name>pat.bin`, the pattern file:
  - All patterns stacked **vertically**, one after another.
  - Each row is `raster_width` words, left-padded.
  - Character n starts at word `raster_width*font_y` and is `raster_width*height` words long
    (TM-115 p20).
  - Total size = total_height*raster_width words.
  - Loaded unchanged into a bitmap area of 16*raster_width x total_height (TM-115 p14).
- `>sys>user>font>fonts.bin`, the font-name registry:
  - word 0 = file length
  - then the names, each terminated by the **delete** character code
  - Written by the editor, not by SIMPOS (TM-115 p95-97; TM-112 p8).
- Metric definitions:
  - `base` = distance from the top of the line to the baseline.
  - `bias` = distance from the baseline down to the bottom of the pattern.
  - line height (editor rule) = Max_height*N + Max_height/E + 1, with `espacement` [N,E] (TM-115 p19).
- Code space:
  - 16-bit codes 0..65535 ("Japanese standards"). Code = row*256 + column; rows and columns are shown
    in hex 00-FF (TM-112 p6, p15).
  - If a font has no space character, `:get_size` of the space code returns defaults computed from
    font parameters. A window's cursor size is derived from the font's space character on
    `:set_font` (TM-115 p16-17).
- Default font: `font_13`, space character 13x19, bias 3 (TM-115 p27, p41, p68-69). PROSE.

### F3. Held `.font` binaries checked against the 1985 format (USAGE data + INFERENCE)

There are 14 held `.font` files. Two families:

**(a) magic `f822`** (`gog-esp/suuji.font`, `suuji2.font`, 1993). Decoded by hand. File size is
predicted exactly for both files (2042 and 4554 bytes).
- 16-bit big-endian words.
- 21-word header: `f822`, line-height?, ?, ?, nchar, strip width in **bits**, strip height, zeros.
  The last 8 words look like a default record.
- Then nchar records of **8 words**: code, x, y, width, height, bias, 0, 0.
  - Codes are JIS row/column, e.g. `2330`-`2339` (digits), `2341`.
  - x accumulates the widths.
- Then one bitmap of strip-height rows x ceil(width/16) words.
  - Patterns lie **side by side horizontally**.
  - Rows are padded on the **right**.
  - Most significant bit is the leftmost dot.
- This is the 1985 design (record with code/x/y/w/h/bias, one area-loadable pattern block), changed
  to a single file, a horizontal strip and 8-word records. INFERENCE.

**(b) 32-bit-field files** (kappa2 `tiny_7.font`, euod `ifr_icon.font`, fuzclust `grape_28.font`).
Header fields look like 13, 10, 127, 912, 9 for tiny_7. **Not decoded.** OPEN.

## SHELL / top level

### S1. Starting and stopping the program (TM-112 p8, eye-read; TM-115 p92, p105-109)

- **From a debugger** (the debugger is the listener in 1.00): `:create(#font_executive,FE),
  :execute_orders(FE).`
  - The program runs "inside the debugger process".
  - A single right click makes `:execute_order` succeed, which ends the repeat-fail loop and returns
    control to the debugger.
  - `:execute_orders(FE).` restarts with nothing lost (TM-112 p8, p19).
  - PRINTED (command line).
- **As an independent process**: `:create(#font_editor,Instance). :create(#process,Process).
  :activate(Process,Instance).`
  - So in 1.00 a program object (nature `as_program`, method `:goal/1`) is run by creating a
    `#process` and `:activate(Process,Program)`. PRINTED.
  - The relevant arities are process create/2 and activate/2 (receiver = Process).
- Start-up takes about 30 s (TM-112 p8).
- **Not on the system menu in 1.00.** TM-115 p109: better to "inherit the class as_e_program and to
  add an entry "font_editor" in the system menu". So `as_e_program` is the 1985 nature for
  system-menu-launchable programs (PROSE). Compare the coordinator's `e_program` in STRUCTURE.md
  section 7.
- Later held code (USAGE, `euod/DEF/def.esp:387-422`): a launcher class with nature `as_program` does
  `:create(#font_editor,FE), :goal(FE)`, running it inline in its own process. It tells the user to
  load `ras:Font>font.font`. So `font_editor` survived as a class with `:create/2` and `:goal/1` into
  later SIMPOS. INFERENCE: it became a system-supplied tool.
- **Stopping:** EXIT calls `:kill(FontExecutive)`. This saves the current font, saves the name list
  and kills all windows and menus, then fails to end the loop (TM-115 p107; TM-112 p20).

### S2. Boot and login of SIMPOS 1.00 (TM-112 p7, eye-read; PROSE)

This is the cold-start procedure for loading a cross-compiled application:
1. Power on and wait for `>` on the green control (CSP) console.
2. `B` <CR> ("boot").
3. `deb` <CR>. The console asks `... (0/1)`.
4. Insert floppies in drive 1 and press `1`: `EXEC`, `WINDOW`, `EDITOR`, `SUPER` in any order, then
   the application floppy last.
5. Each floppy prompts `EXEC (Y/N)`, then `Another volume (Y/N)`.
6. After `n`, the system asks for the date and other questions (answer CR).
7. "a login message will appear on the PSI bitmap screen".

Two facts about loading:
- "the system does not support on time loading of cross compiled programs". An application is linked
  in at boot from floppy.
- INFERENCE: EXEC / WINDOW / EDITOR / SUPER are the SIMPOS 1.00 boot volumes (kernel+executive,
  window system, editor, supervisor?).
