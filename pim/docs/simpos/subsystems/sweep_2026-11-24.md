# Second sweep of the held material for SIMPOS-derived code and manuals (2026-11-24)

The first subsystem dive found that some held *application* archives carry pieces of SIMPOS itself
(`finds.md` §1-3: cil's copy of the SIMPOS 6.1 Librarian, cil's KL0 built-in table, CAL's debugger
descended from `<SIMPOS.E.DEBUGGER>`). This sweep searched every held file for more of the same,
and for any copy or table of contents of the missing I/O manual
「ESPプログラミング説明書－入出力管理編」 / 「SIMPOSプログラミング説明書(II) 入出力編」.

Nothing here is committed from the archives. Citations are `archive/path:line`, where `archive` is
the archive's base name (`morphana` = `ifs/natural-lang/cesp/morphana.tar.Z`, `linguist` =
`ifs/natural-lang/cesp/linguist.tar.Z`, `kwic-cesp` = `ifs/natural-lang/cesp/kwic-cesp.tar.Z`,
`cal-esp` = `ifs/kbms-clp/simpos/cal-esp.tar.Z`, `INFO` = `ifs/INFO.tar.Z`, `ESPtex`/`ESPtex-j` =
`ifs/manuals/esp/ESPtex{,-j}.tar.Z`, `cil` = `ifs/natural-lang/simpos/cil.tar.gz`). The archives'
own manifests are `../../nonlocal/IFS_MANIFEST.md`, `ICOT_OTHER_MANIFEST.md` and `MANIFEST.md`.

## 1. What was searched, and how

**Unpacking.** Every file under `pim/docs/nonlocal/` was tested by its first bytes (compress, gzip,
bzip2, zip, ustar, lzh) and unpacked with `bsdtar` into a fresh scratch tree, recursively, to depth
6: 475 archives, 213,064 directory entries, 1.3 GB. Of the entries, 176,913 are empty files: bsdtar read decompressed
trip-simulator data in `contract-research/96/DH8-23` as mtree archives. The decompressed data files themselves
were searched. That leaves **36,151 real files**, 602 of them images. A second pass looked for archives the magic test missed
(old v7 tar without the `ustar` magic, shar, uuencode, cpio). It found nine inner tars and unpacked
them too:
- papyrus `source.tar`, kwic-cesp `kwic_install.tar` and its `source/engine/engine_cvf`
  (a tar with no suffix), cal-cesp `cal.package.tar`, exreps `exreps.tar`;
- morphdic `syll_install.tar`, pathway `dbhelp.tar`, cuprolog `cupsrc/CHANGES` (a tar named
  CHANGES).

Gaps in the unpacking:
- `ifs/contract-research/96/DH8-26/H8-26.tgz` holds an inner `H8-26.tgz` of 0 bytes.
- One member of `exper-apps/pimos/mssd.tar` (a protein database) collided with a directory.
- `icot-other/pub/cuprolog/demo/gn/sounds/httpd_src.tar` (NCSA httpd) was listed, not searched.

**Text search** (every non-image file, raw bytes, so any encoding with ASCII letters; lines cut at 4,000 bytes):
- the strings `SIMPOS` (any case), `patch class`, `<SIMPOS.`, `simpos##`, `library_utility`,
  `standard_io_window`, `as_program`, `wincs`, `pmacs`, `coordinator`, `system_menu`,
  `librarian`, and `Version 2.`-`7.`;
- PSI file stamps `host::>sys>...` (every one tabulated by directory), `>sys>` paths outside
  `>sys>user>`, and DEC-20 stamps `<DIR.SUB>FILE.EXT.n`;
- copyright lines, filtered for Mitsubishi, Oki, Fujitsu, Hitachi, Toshiba and Matsushita;
- every `class NAME has|with` line, compared with the 496 names in `../required/classes.tsv`.

**Japanese.** Every file with 8-bit bytes or JIS escapes was decoded (ISO-2022-JP, EUC-JP,
Shift-JIS, UTF-8 in turn) and searched for 入出力管理編, 入出力編, プログラミング説明書, 操作説明書,
使用説明書, ＳＩＭＰＯＳ, ESPプログラミング, ウインドウ/ウィンドウ, ライブラリアン, システムメニュー,
コーディネータ and デバッガ.

**Binaries.** The 1,682 non-text files that do not decode as Japanese text were scanned for these
words as raw 16-bit JIS without escapes, in both byte orders and in 32-bit cells. This is how PSI
packages store strings.

**PDFs.** All 1,428 PDFs went through `pdftotext`. The 1,417 under `nonlocal/` (TR/TM scans, IPSJ
papers) have **no text layer**, so this sweep could not search them. They were read by eye in the
earlier passes (`notes/trtm_*.md`, `notes/ipsj.md`). The 11 with text are 1998 contract-research
papers with no hits. Japanese PostScript (`man30.j.ps`, `ESPps-j`) was searched only for its ASCII
strings. The ESP manuals' TeX sources (`ESPtex-j`) were searched instead.

## 2. Hits: SIMPOS code and SIMPOS documentation

### 2.1 SIMPOS's own `world` classes, carried in a CESP application (HELD-SOURCE, new)

`morphana/_simpos/` is the LAX morphological analyser's shim directory, "Programs to cover the
difference between ESP and CESP" (`morphana/README:59`). Three of its files are SIMPOS source:

| file | stamp | class | methods defined (all class methods) |
|---|---|---|---|
| `pathname.esp` | `:6` `icpsi372::>sys>simpos7D>supervisor>world>PNAM1.esp`; `:7` `icpsi900::>sys>user>tateishi>world>PNAM1.esp.2, 17-Feb-88` | `pathname` (`:13`) | `last_name/4`, `get_last/4`, `append/4`, `append_names/3` |
| `name.esp` | `:6` `icpsi900::>sys>user>tateishi>world>NAM1.esp.2, 17-Feb-88` | `name` (`:12`) | `ident/3`, `type/3`, `type_string/3`, `type_version/3`, `ident_type/3`, `version/3`, `version_string/3`, `check_name/3`, `check_ident/2`, `check_type/2`, `append_type/4`, `sort/3`, `key/3`, `version_number/3`, `make_name/4`, `full_name/4`, `key_version/4`, `legal_characters/3`, `allowed_characters/3`, `illegal_character/2` |
| `e_string.esp` | `:6` `icpsi900::>sys>user>tateishi>world>EST1.esp.5, 17-Feb-88` | `e_string` (`:14`) | `cut_space/3`, `nonspace/3`, `nonspace_from_tail/3`, `not_element/3`, `character_position/4`, `count/4`, `split/4`, `separate/4`, `replace/5`, `string_sort/3` |

**Provenance.**
- `pathname.esp` names its source: the file `PNAM1.esp` in the `supervisor>world` directory of a
  tree called `simpos7D` on machine icpsi372. This is the only `>sys>simpos...` stamp in all the
  held material, and the first held file stamped as coming from a SIMPOS *release* source tree.
  SIMPOS 7D is not otherwise attested; the label is read as the stamp gives it.
- The 1988 user copy `tateishi>world>` has the same directory name, `world`. INFERENCE: `name` and
  `e_string` are copies of the same SIMPOS directory.
- The person "tateishi" is not in `../trtm_table.tsv`. No claim is made about who he was.

**How far the bodies are SIMPOS's.**
- `pathname`: the CESP port replaced the `>` component split with `/` (`:53-56`) and converts the
  result to an 8-bit string (`:31`). The SIMPOS cases are kept as comments, and they are evidence:
  - `[2]`: Upath is `"/"` or `"Node::>"`;
  - `[3]`: Upath is `"Logical_name:"`;
  - `[4]`: Upath is `"...>Name"`, marked `% Patch 6.13` (`:79-92`).
  `check_local_pathname` still splits at `>`, and `append_names` joins with `>` (`:93-111`).
  Not carried: `remote_or_local/6`, `check_pathname/3`, `last/4` and `straighten_up/5`, which held
  programs call (`../required/requirements.tsv`).
- `name` and `e_string` contain no CESP-specific call. Read them as SIMPOS 1988 code.

**What they settle** (the `other` partition; no subsystem spec covers it):
- SIMPOS file-name syntax `ident.type.version`, as the class enforces it:
  - an ident is 1-44 characters (`name.esp:83-88`);
  - a type is 0-10 characters (`:91-96`);
  - neither contains a dot;
  - the illegal characters are `>` `*` `?` `:` and space (`:163-164`);
  - a missing version gives `version_number` = -1 (`:127-130`);
  - `sort/3` orders by key, then by version.
- Every `name` method the held programs need: `ident/3`, `type/3`, `append_type/4`, `sort/3`,
  `ident_type/3`, `version/3` and `check_name/3`.
- `pathname`'s `append/4`, `last_name/4` and `get_last/4`.
- Every `e_string` method held programs call: `split/4`, `replace/5` and `nonspace/3`.

Grades: HELD-SOURCE (application-carried copy). Rows are in `notes/sweep2.tsv`.

### 2.2 CESP substitutes for SIMPOS window mixins, documented (CESP substitute, new)

`linguist` (1991, LINGUIST on CESP) has its own window library. Its software manual says which
classes stand in for SIMPOS's (`linguist/doc/Manual/Soft/software1.tex`, ISO-2022-JP):
- `with_margin` is "a substitute class for SIMPOS's class with_margin" (`:802-827`);
- `as_markers` is "a substitute for SIMPOS's class as_markers, with the same function as that
  SIMPOS class" (`:829-871`);
- `as_outputs` is a substitute for SIMPOS's `as_output` that implements "part of" its function
  (`:891-920`).

The sources are `linguist/prog/with_margin.esp`, `with_marker.esp` and `as_output.esp`. They give:
- `create_marker/7` as `(W, X, Y, Width, Height, Type, ^Marker)` (`with_marker.esp:21-25`). The
  marker types are `box`, `line` and `reverse` (`:216`). This bears on gap G18.
- `get_margins/5` as `(W, ^Left, ^Right, ^Head, ^Tail)` (`with_margin.esp:31`), against TM-125's
  `set_margins/5`. This bears on gap G21.
- `get_marker_position` with arity 3 (`with_marker.esp:79`). The held SIMPOS callers use arity 4, so
  here the substitute differs from SIMPOS.
- `as_output`'s write methods, which do not settle G3:
  - `move_cursor/3`, `get_cursor_position/3`, `write/2`, `write_lines/2`;
  - `write_line/2,3,4`, `put_line/2`, `put_line_at/2`, `clear_line/1,3`.

`linguist/prog/window.esp:18-260` composes `standard_io_window`, `standard_menu`,
`standard_superior_window` and `standard_choice_window`, and their variants, from CESP mixins:
`as_superior`, `as_input`, `with_label`, `with_border`, `with_font`, `as_mouse`, `as_input_buffer`,
`as_cursor`, `as_output`, `as_scrollbar`, `as_graphic`, `with_superior_input_buffer`, `menu` and
`dialogbox`. This is CESP's library in use. It corrects `web_search_2026-11-24.md`'s "neither
[CESP archive] shows the CESP `#window` library in use": that note had looked only at cal-cesp and
kwic-cesp. The recipes are CESP's, not SIMPOS's, and grade only as an analogy for G3/G4.

Also substitutes, all application-written and none SIMPOS source:
- `linguist/prog/mh_index.esp:5` (`monogyny_hash_index` over `hash_index`) and `as_scroll.esp:5`;
- `morphana/_simpos/bfiles.esp` and `kwic-cesp/source/binary/bfiles.esp`: `binary_file`,
  `binary_file_accessor`, `string_buffer`, `binary_file_marker` and `binary_file_tap`, rebuilt on
  Unix files;
- `morphana/_simpos/str.esp`, `frozen_term.esp`, `stdiobuf.esp`, `lax_dir.esp` and `lax_name.esp`;
- `morphana/_source/messenger.esp:7`, where `show/2,3` and `confirm/2,3` just print the message;
- `kwic-cesp/source/engine/for_rename.esp:7-21`, where `as_esp_parser` has nature `as_parser` and
  `as_esp_unparser` has nature `as_unparser`, plus a `pathname:last_name/4`.

### 2.3 The CAL debugger's operation manual (DERIVED documentation, new)

`cal-esp/deb_jman/debug.tex` is 「ＣＡＬデバッガ操作手引書 第2.12版」, dated 1992-07-01. The
debugger it describes is the one descended from the SIMPOS debugger (`finds.md` §3), and it assumes
SIMPOS 7.0 (`:29`). It prints:
- the debugger window, with title `CAL Debugger`, a `variable` pane, and the command column `Step`,
  `Skip`, `Leap`, `Fail`, `Retry`, `Print`, `No trace` (`:49-64`);
- the meaning of each trace command (`:153-172`);
- the `Debugger Menu` items: `Mode_Leash`, `State`, `Set_spy`, `Inspector`, `Re_display`, `Abort`
  and `[Exit]`. It is opened by a double left click on the debugger window (`:127-151`);
- the trace line `(1) 1 CALL method> ham:horse_and_man(3,4,A,B) ?` (`:105-117`);
- the Mode_Leash window: `mode`, `display`, `leash`, `target`, `trace`, `leash`, with gates `CALL`
  `EXIT` `REDO` `FAIL` (`:174-226`);
- the State window, `CAL stat`: `Depth>`, `Length>`, `macro class>` (default
  `esp_macro_expander`, which must inherit `as_macro`), `top-level redo`, `display vars : all used
  new no`, `variable menu`, `heap counter` and `time` (`:229-282`);
- the Spy window: `PACKAGE>`, `CLASS>` (all, public or local classes), `PREDICATE>`, `class` /
  `instance` / `local : yes no`, then `set`, `reset`, `reset all`, `refresh` and `exit`
  (`:285-339`);
- the init file `me:cal_debugger.ini`, with its terms (`:356-372`) and the five leash levels as
  `target(Method,Local,Predicate,Builtin)` and `gate(CALL,EXIT,REDO,FAIL)` vectors (`:376-386`).

The manual agrees with its source. The leash list full/tight/half/loose/no is
`cal-esp/deb2.12/create.esp:1415-1421`, and the display modes are `entry.esp:63,209`. It points to
two SIMPOS manual chapters:
- the 「SIMPOSプログラミング説明書」 section 「標準入出力（ホロフラスティング）」, for
  depth/length elision (`:236-237`);
- the 「ＳＩＭＰＯＳ操作説明書」 section 「インスペクタ」 (`:346`).

So the programming manual has a standard-I/O chapter that covers holophrasting. This is the
`set_max_depth`/`set_max_length` behaviour, gap G7. Grade: DERIVED (CAL's own debugger, 1992). It
supports `shell.md` §5.4 by analogy only.

### 2.4 The held ESP manual, read for the remaining shell gaps (PRINTED/PROSE; held before, not read for these)

`ESPtex/program-e.tex`, with the Japanese original `ESPtex-j/program-j.tex` (ICOT, 1990):
- **`get_slot/3` and `set_slot/3` belong to class `class`.** `Obj!slot` is the macro for
  `:get_slot(Obj,slot,Value)`, and `Obj!slot := V` for `:set_slot`; both are "method call ... of
  class `class`" (`program-e.tex:5987-5988`; `program-j.tex:5802-5803`). This settles the owner
  for shell gap 1 / gaps.md rank 4: every object answers them. The other three generic methods,
  `class_object/2`, `refute/3` and `method/3`, are not in either manual.
- **`stop_watch`** (`program-e.tex:10018-10045`; `program-j.tex:9416-9430`): a printed method
  table with `create(#stop_watch,^W)`, `start/1`, `stop/1`, `reset/1` and `show(W,^Time)`. It
  states:
  - the time measured runs from reset and start to stop;
  - `show` gives "an instance of time", and only after `stop`;
  - a measurement cannot span two days.
  This settles most of shell gap 3 (`get_count/2` stays usage-only).
- **`standard_io_buffer`** example (`program-e.tex:6736-6745`; `program-j.tex:6470-6480`):
  - `create/2`, then two `putl` and two `gett` read the two terms back;
  - `putt` twice, then `getl`, gives `"[1,2]p(1,2)"`, so `putt` writes no separator;
  - both editions print `put1`/`get1`, read here as `putl`/`getl`.
- **`symbolizer`** example (`program-e.tex:6750-6765`): `get_atom/3` answers `fail` when the atom
  is not interned, `enter_atom/3` creates it, and `get_number_string/4` takes a radix.

### 2.6 The PIMOS manual's SIMPOS-side set-up steps (PRINTED, found by the final search group)

The English PIMOS manual (`pimosman.tar.Z`, `Eman/`) was already used for the FEP
(`../../fep_services.md`), but its SIMPOS-side passages had not been read for the subsystems:
- **`e-network.tex:22-56`** prints an excerpt of SIMPOS's own TCP/IP configuration file
  `>sys>tcpip>net_config.dat`. Its `@spawn` / `@@process` section maps service numbers to SIMPOS
  classes: 5 `simpos##talk_input`, 6 `simpos##talk_output`, 8 `simpos##x_server`, 9
  `simpos##remote_printer`, and 2000 `spawn`. PIMOS adds `2010,pimos_remote_login_server;`. The
  same chapter names the SIMPOS files `>sys>tcpip>host.dat` and `>sys>net>process>mylia.dat`
  (LIA-net), and gives the line format of the latter (`:64-75`). These are SIMPOS system classes and
  files that no other held source names. Grade PRINTED (a 1990s PIMOS manual, version not stated in
  the chapter).
- **`e-strio.tex:14-31`** (PROSE): "simpos##as_resource is a class that inherits simpos##as_program
  due to SIMPOS rules", and window and filter classes inherit `simpos##as_resource`. So a class that
  inherits `pimfep##as_pimos_string_io_device` (which inherits `as_program`) cannot also inherit
  them. This settles one link of the shell's `as_program` hierarchy (`shell.md` §3).
- **`e-login.tex:8-48, 226-233`**: the SIMPOS system-menu item "Login PIMOS" and package
  `mpsicsp`. Known (`../../fep_services.md:333-361`).

No method of these classes is printed, so no coverage row changes.
