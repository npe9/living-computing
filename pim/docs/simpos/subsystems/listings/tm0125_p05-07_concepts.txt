--- 2.1 Window System (PDF p3)
 - PSI is multi-process but has ONE console; the window system supplies "logical terminals named window"
   on bitmap display, keyboard and mouse.
 - Window system controls window allocation and the data path from input devices to processes;
   inter-process communication management is the coordinator's job (refs Tsuji 84 = TR-046, Kurokawa 84 = TR-061).
 - Fig 1 (PDF p4): Coordinator + Processes / Window Subsystem / Bitmap Display, Mouse, Keyboard handlers,
   Kana-Kanji Translation Module (already in tm0125_p04.txt).

--- 2.3 Hierarchy of Window (PDF p5)
 - Example motivation: an editor window with a text window and a command-input window as sub-windows.
 - Tree: SCREEN at the top; ordinary windows are sub-windows of the screen; any window may have sub-windows.
   Sub-windows are managed by their superior window (screen manages ordinary windows).

--- 2.4 Input Management (PDF p5)
 - Keyboard: not shared; its input goes to the one "SELECTED WINDOW", which the user determines.
 - Mouse: associated with the mouse cursor, roams the whole screen, shared by displayed windows; mouse input
   goes to "the shown window on which the mouse cursor is positioned".

--- 2.5 Output Management (PDF p5-6)
 - Statuses: exposed/deexposed and shown/unshown.
   exposed  = a sub-window not hidden by another sub-window of the same superior; deexposed = hidden.
              (status among siblings of the same superior)
   shown    = the window is exposed AND all its ancestors are exposed -> fully shown on the screen.
   unshown  = the window or any ancestor is deexposed.
 - Output permission: four types; the user selects one per window:
   1) WAIT    wait to output until the window becomes fully shown on the screen.
   2) NOTIFY  display a message telling the user the window wants to output, through a special window
              ("NOTIFY WINDOW", prepared by the system).
   3) OUTPUT  do the output immediately; if unshown, output goes to the bitmap area that saves the window's
              display image, and only the shown part appears on screen.
   4) SHOW    show the window compulsorily and do the output.
   Caveats printed: OUTPUT may leave output unseen; SHOW changes the selected window (keyboard input then goes
   to the newly shown window). Authors recommend WAIT and NOTIFY normally.
 - Kanji: PSI uses 16-bit character data; kanji handled the same as alphabetic characters by the window system.

--- 2.6 Temporary Window (PDF p6-7)
 - Appears at the position of the mouse cursor; disappears when the mouse cursor goes out of it.
 - Features: 1) never hidden by an ordinary window; 2) when no longer needed it is taken off the screen, not
   hidden; 3) it saves the display image of the area it covers.
 - (4.2, PDF p11 = folio 10: as_popup_window: a popup window is a temporary window NOT removed when the mouse exits.)

--- 2.7 Menu Window (PDF p7)
 - Accepts only mouse input (pointing and click); no keyboard input, no output request. User moves the mouse
   cursor onto an item and clicks; the prepared operation is done for that item.

--- "2.7" [=2.8] Choice Window (PDF p7)
 - For items with many alternatives or typed values. Shows item label and the alternatives or the current value.
   Value items (SIZE, POSITION ...) are changed by selecting the item and typing; enumerated items (PERMISSION,
   FONT ...) show the current element in reverse video and are changed by clicking.
