## Programming system = set of expert processes (p03-04)
"we consider the programming system of SIMPOS to be a collection of expert processes" (interpreter, editor,
compiler, games, DBMS). No explicit supervisory process like the Unix shell; the Coordinator is a background
process. ESP itself serves as command language, the interpreter as command interpreter (p04).
Coordinator functions (p04): send user commands to experts via the window; create/activate/suspend/resume/delete
experts; special commands; inter-expert communication via the whiteboard; Help; logging on, resource-manager
interfacing.

## Representation (p04-06)
- expert = instance of e_process with attributes: an e_program (special class of program; "The instance of the
  'program' has a special method 'goal' to execute the main function. The instance can also be 'invoked' in the
  process environment"), an e_window, an e_port (special Port, used to talk to the Coordinator), the expert name
  (key in e_process_pool, derived from the e_program name in the user's e_program_directory).
- set of experts = an instance of e_process_pool, derived from list_index (later cascade_index); active object for
  broadcast/remember (p05).
- e_window holds a translation_table and the e_process; SIMPOS uses a 16-bit code based on JIS kanji code;
  translation happens in the window process (p06). Meta-commands listed: kill, lull, status, visit, memorize,
  broadcast, remember, read_from_whiteboard, write_to_whiteboard, system_menu_invoke (p06).
- Expert identified through a special port maintained by the window manager (p06).

## Figure 1 (PDF 12, eyed): class relations; encircled = defined in the Coordinator; solid = is-a, dashed = has-a
coordinator is-a program; coordinator has-a e_process, whiteboard, e_port.
e_process is-a process; has-a e_program, e_port, e_window.
e_program is-a with_goal_demon and e_program_core; e_program_core is-a program; e_program_core has-a
help_info_dictionary. e_port is-a inter_process_port; inter_process_port is-a port.
e_window is-a window; e_window has-a translation_table; translation_table is-a default_translation_table.
Not encircled (defined elsewhere): program, process, port, window.

## Meta-commands (p07-08): visit, create (from e_program; e_window and e_port created automatically), kill (releases
all resources incl. the hardware process), lull (suspend execution; distinct from I/O suspension when not visited),
arouse, memorize (history table), remember, broadcast (to all experts executing a class of e_program), write / read
(whiteboard), invoke the system menu (create experts, log on, Help, file system management).

## Customization (p08-10): class 'user' per SIMPOS user with an expert directory (names -> e_program); system_menu
shows that list at login; users may modify the system standard directory at run time. Key command table per
e_window, changed via 'key-command_table-change' command; mouse clicks encoded as special keystrokes.
