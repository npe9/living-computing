# TR-057 Overall Design of SIMPOS (Takagi, Yokoi, Uchida, Kurokawa, Hattori, Chikayama, Sakai, Tsuji; April 1984). 13 PDF pages, OCR read in full (simpos2/ocr/tr0057), figure and table read by eye (300 dpi).

No ESP listing. Prose design overview plus Table 3-1 (window status, listings/TR-057_p06.txt) and Fig. 4-1 (debugger box model, listings/TR-057_p08.txt).

## Layers (p3, p5)
- SIMPOS = programming system (PS) + operating system (OS). OS = kernel, supervisor, I/O media subsystems (p5: "consists of 3 layers"). PS = subsystems called experts, coordinated by the coordinator (p3).
- Subsystem list (p3): Window (OS), File (OS), Network (OS), Debugger/Interpreter (PS), Editor/Transducer (PS), Library (PS).
- Kernel (p5): processor manager (multiple process environments), memory manager (allocate/deallocate, garbage collection), I/O device manager. SKETCHED.
- Supervisor (p5): pool, directory, stream, channel, port, process/program, environments (program, library, world, universe). "World is a sequence of directories held by a process as its working world. A universe is a system directory tree held in a class slot of class directory." SKETCHED (concepts, no interfaces).

## ESP implementation note (p4-5)
- Cross compiler ESP->KL0 available March 1984. Each object has a slot holding a database of codes for its axiom set; slot access by slot-name atoms using KL0 built-in hashing (p5).

## Window subsystem (p5-6)
- Window = instance of the window class; methods are its predicates. Hierarchy: logical screen at the top; sub-windows must lie inside superior. 5 states selected/shown/exposed/overlapped/deactivated with Table 3-1 giving key-in/mouse/output behaviour (done/wait/fail) per state. Window manager slot selected_window. Mouse click handled only in shown windows. REIMPLEMENTABLE: the state->I/O table.
- Echoing etc. done by transducer and coordinator, not window subsystem.

## File subsystem (p6-7)
- Files: binary files, table (fixed-length record) files, heap (variable-length record) files; records by position and/or key via an index file; planned "binder" for virtual files; instance file (permanent objects as instance records); directory file associates instance record with a name; permanent directory = directory backed by a directory file. SKETCHED.

## Network (p7)
- Classes node, socket, cable, plug; remote channel; remote objects. SKETCHED (names only).

## Programming system (p7-10)
- Experts = processes with an e_window. Coordinator: work-behind process (no shell); forwards key commands, creates/deletes/activates experts via system_menu, handles special commands, whiteboard. Per-user directory of experts (expert name -> program name), inherited from system common directory; per-window key command table. SKETCHED.
- Debugger/Interpreter (p8-9): procedure-and-clause box model (Fig 4-1: ports Call/Exit/Fail/Redo at procedure; Unify/Next, Pick/Miss, Exit/Redo at clause). Interpretive and compiled code call each other; debugger cannot trace compiled code. REIMPLEMENTABLE at port-model level.
- Editor Edips (p9): structure editor using operator-precedence grammar with user-definable parentheses; 6 token categories (atom, prefix, infix, postfix operator, left/right parenthesis); 2-3 precedence levels for ESP. Parser/pretty-printer are separate utilities shared with compiler/interpreter/debugger.
- Library (p10): class source file / class template file / class object file per class; one class per file; template built from one source file, holds all except inheritance analysis; predicates kept as interpretive code, compiled on request, both kept; class object built from templates with inheritance resolved = executable image. All predicate invocations via indirect references (indirect word points to interpreter entry for interpretive code). Compiler is a subroutine of the library; compiles one predicate from interpretive code in main storage; template file rebuilt after compilation. SKETCHED (no file formats).

## Development tools (p10-11)
- Cross tools in Prolog: ESP cross simulator, KL0 cross compiler, KL0 cross assembler, PSI microprogram cross assembler, cross linkage editor, microprogram table generator; some in PASCAL. Customisable Assembler (Takagi 1983): KL0 definition ~500 lines, microprogram definition ~1100 lines, kernel ~900 lines Prolog.
