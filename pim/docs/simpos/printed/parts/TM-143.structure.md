# TM-143 「SIMPOS（逐次型推論マシンPSIのOS）―ユーザ・インタフェイスと開発過程―」(Ishibashi et al., Nov 1985). 8 PDF pages, Japanese, poor scan. Read by eye (pp2-8) at 250-600 dpi; transcription in listings/TM-143_p02-08.txt. Translations below are TRANSLATION (mine).

## Layers (p2) -- five groups, with a concentric structure figure
- (1) Resource management program (kernel): processor management (multiprocess environment), memory management (allocation, address-space management), device management, **IPL (Initial Program Loader): loading and initialising the system body** -- IPL is placed in the kernel.
- (2) Execution management program (supervisor): process, pool, stream (IPC), world ("directory function as the process's execution environment"), **clock management (date, time, alarm, stop-watch)**, **remote object management** (objects on other PSIs over the LAN), **kanji processing (kana-kanji conversion input)**, **system tracer**, **situation** (flexibly changes how errors etc. are handled according to the situation).
- (3) I/O media: window, file, network. (4) Programming system: coordinator, editor, transducer (string <-> structure representation of programs/data), librarian (compiles; manages code and objects), interpreter/debugger. (5) Manipulators: menu front-ends to utilities -- window, file, network, whiteboard manipulators (p3).
- Figure (p2): rings hardware / kernel (processor, memory, device, kanji, tracer, IPL) / supervisor (process, pool, stream, world, clock, remote object, situation) / I/O / PS; KL0/ESP boundary marked. Compare TR-057 (3 OS layers) and TR-086 ("kernel operating system" containing I/O).

## User interface (p3)
- Login: user name + password, then per-user initialisation: system-menu items (e.g. add "my program"), **logical names for directories, default `me:` = `>sys>user><login name>`**, and an initialisation program run at login. REIMPLEMENTABLE: the logical-name convention.
- System menu = SIMPOS's command processor, called any time by two right mouse clicks; columns EXPERTS (several instances each may run concurrently) and MEDIA SYSTEM (only one instance each); start/stop/suspend/resume by mouse. Screenshot items (low confidence): EXPERTS generalist?/debugger/editor/file_manipulator/librarian/terminal?; MEDIA SYSTEMS window_manipulator/network/shell?/whiteboard/login/shut down?.

## Librarian (p4) -- the most concrete statement of the class pipeline in Japanese
- Library manages three forms per class: source (ESP text); template (per-class info excluding inheritance: slot information, method and local-predicate code -- both kinds of code, interpretive and machine, kept here -- plus names of inherited classes and referenced classes); object (executable form after inheritance resolution).
- Building a class object: make the template; resolve inheritance using the templates of the inherited classes (継承解析); make the executable object.
- Auto-load: running a class requires loading all classes it uses directly or indirectly (inherited and referenced classes); done automatically by the librarian.
- Inheritance analysis is done statically at registration to speed up OO calls; so adding/deleting methods (incl. demons) or slots, (some) method-body changes, or changing a slot's initial value forces rebuilding every class that inherits the changed class; local-predicate changes only need re-registering that class; classes that merely reference the changed class never need re-registration. REIMPLEMENTABLE as a dependency rule.
- Debugger: interpretive code traced; compiled code callable; Procedure and Clause Box model reprinted.

## Window classes (p6)
- Window system built by multiple inheritance from part classes: basic (temporary-window, inferior-window), attribute (with-border, with-label, with-two-labels, with-margin), function (as-output, as-scroll, as-graphic, as-input, as-mouse-input), transducer (as-esp-transducer, as-standard-transducer), menu (as-menu, as-multiple-column-menu, as-scrolling-menu), menu extension (as-single-select, as-multiple-select, as-on-off); ready-made window and menu. Hyphens as printed.

## Size (p6): SIMPOS version 1.5: ~145,000 source lines, 960 classes, ~15,000 predicates; predicate breakdown table (principal class 4405 / instance 5349 / local 5?49 / runtime 104; demons; method predicates; slot initiation). Whole system from device handlers, memory and process management up to the programming system is written in ESP.

## Development and boot path (p6-7)
- DEC 2060 (cross system: edit, cross-compile, link) -> file transfer -> DEC LSI-11 (SVP) -> floppy -> PSI (CSP console); on-machine debugging via CSP with the ESP tracer and system tracer. SKETCHED: floppy format absent.
- Release history (Showa dates): 58/5 (1983-05) group formed; 58/12 PSI #1 delivered; 59/3 firmware complete; 59/5 OS bring-up version; 59/9 OS part; 59/10 international-conference demo (no PS); 59/12 SIMPOS 0.7; 60/2 0.? ("usable"); 60/4 1.0; 60/9 1.5 (UI improved); ?/? 2.0 (reliability, functions).

## Performance and memory (p8)
- One-character input 2 s -> ~1?0 ms (software) -> 21 ms (firmware); output 3 s -> 14 ms -> 7 ms. Process switch 21 ms -> 2 ms. Firmware ESP runtime: methods ~5x faster, slot access 10x. Keystroke-to-display 28 ms (35 chars/s). Improvements: ESP runtime x3, polling in bitmap handler interrupt handling, merging the bitmap handler with the window manager, connecting the keyboard handler directly to the user process.
- Memory: global stack cannot shrink except on backtracking (system programmers must backtrack to free it); heap area used by objects and strings is reclaimed only by GC; memory use measured via the CSP. A call counter tool exists.
