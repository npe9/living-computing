# TM-401 「逐次型推論マシンPSIのネットワーク・システムの概要」(東 吉郎 他, Oct 1987). 13 PDF pages (folio = PDF-1), Japanese, clean print. Read by eye: whole report at 60 dpi, pp8 and 10 at 300 dpi. TRANSLATION mine. No ESP listing.

## Physical (p2-4, Fig. 1)
- PSI-net: ~100 PSIs at ICOT and 17 companies/labs, LANs (Ethernet type) joined over the DDX packet network. Elements: host (PSI or general-purpose machine, currently VAX; hosts providing services such as mail are "server hosts"), LIA (LAN interface adapter), TC (transceiver), BRG (bridge), GW (gateway over DDX), NCLIA (network-control LIA: management/logging), unit network (one coax), composite network (unit networks joined by BRG); each composite network has a network name.

## Software (p5-7, Fig. 2)
- Layers: LIA software (LIA-LIA protocol, basic communication), NCP (Network Control Program: process-to-process communication over the LIA, adds reliability), application programs (mail system, file transfer, etc.). NCP modes: connection mode (logical channel, reliable, ordered) and datagram mode (no connection; reliability/order not guaranteed); both 1:n capable. NCP user interfaces: network listener interface (all NCP functions; for servers), simple I/O interface, LIA interface (direct LIA use).
- Network software is part of SIMPOS, written in ESP; transmitted data is exchanged between processes as "message objects" holding the data plus objects needed for communication (p5).
## Process addressing (p8, sec. 4) -- REIMPLEMENTABLE at concept level
- Each communicating process has a process address unique in PSI-net ("physical address"), internally a 32-bit number. A process symbolic name (プロセス記号名) maps a string to process addresses; network I/O identifies processes by symbolic name; one name may denote several addresses (group name, 1:n). The mapping is kept in a file on each PSI; changes are sent from a server host over the network. Bit layout of the 32-bit address not given.
## Applications (p7-11)
- Talk (two-PSI real-time conversation, partner chosen from logged-in users of the composite network; 1-char / word / line transmission modes), remote screen display (periodic copy of another PSI's bitmap), mail (mail boxes on server hosts, forwarding when the destination PSI is down, refs SMTP [Postel 1982]), electronic bulletin board, file manipulator remote access.
- File manipulator remote access (p10): operate on files/directories of other PSIs or mainframes; "internally uses the remote object mechanism. SIMPOS has objects and access to an object is a 'method call'; the remote object mechanism lets a method call to an object in another host (remote side) be handled like one in the own host (local side)." Functions: directory display, file copy (local->remote, remote->local, remote->remote), append, delete, undelete (if not expunged), expunge, purge (keep latest versions), attributes, type (as characters), dump (hex), rename, create directory, delete directory, security (passwords; access rights read/write/delete per user; restriction scopes: one PSI, composite network, whole network).
## Status (p12): 1987-09 sites table (Hitachi, Toshiba, Fujitsu, Oki, Sharp, Matsushita, NEC, Mitsubishi, ICOT 41 PSIs...); TCP/IP support planned; access to CSNET planned.
