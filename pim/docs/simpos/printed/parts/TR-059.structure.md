## Position (p03)
OS part has three layers: kernel, supervisor, input/output medium systems; the file system is one i/o medium
system managing disk storage. Provides data storage (files), object storage (instance files) and, partly,
knowledge storage (a planned "binder" making virtual files from multiple files -- not designed, p05-06, p33).
Motivating permanent objects: file objects in the VTOC, user objects (login), node objects (network) (p04).

## Volume structure (p06-10) -- logical structure given, no byte formats
- volume object over a disk object (disk defined by kernel device management). Volume descriptor in a fixed area:
  volume id, VTOC, root directory file, free page pool. :mount(Volume,Disk), :dismount(Volume) (p06).
- Figure 2.1: volume descriptor -> VTOC (file file) and root directory file; files (p07).
- Fixed-length disk pages; :allocate(Volume,Page), :deallocate(Volume,Page); direct access only, by disk page
  address; only the file manager uses volume access (p07-08).
- region = area of pages storing a file's records; region descriptor (page table, region size) stored in a VTOC
  entry as part of the file descriptor (file type, record size). "the VTOC is constructed as an instance file of
  file objects, and the first entry of the VTOC describes itself" (p08, Fig.2.2).
- page table occupies one page; ordinary entries map logical to physical pages; "the last few entries contain the
  addresses of the next level page tables"; regions grow dynamically (p09, Fig.2.3). No multi-volume files.
- NOT given: page size, descriptor layouts, entry counts, VTOC record format, on-disk location of the fixed area.

## Files (p10-20) -- interface printed; enough to reimplement the API
- mixin as_file: binary, table, heap files; direct and sequential modes; positional and indexed access (p10).
- :open(#file,File,Name), :create(#file,File,Name), :close(File), :remove(File) (p11).
- buffer object over a KL0 integer vector or string: :record_data, :data_size, :set_data_size (p11-12).
- file marker: :postion [sic] / :set_position; :start_marker, :end_marker; marker not updated when EOF moves
  (p12-13).
- direct access: :read/:write(File,Buffer,Marker), :add(File,Buffer), :delete(File,Buffer,Marker); write and read
  sequences printed (p13-14).
- file tap: :tap(File,Tap); :read/:write(Tap,Buffer) advance; :marker, :beginning, :end, :move, :move_to_beginning,
  :move_to_end (p14-15, Fig.3.1).
- binary file: fixed 1- or 2-byte records, position = byte (two-byte) offset, multi-record transfers; binary tap
  advances by records accessed (p15-16). table file: fixed-length records, record size at creation (p16-17).
  heap file: physical record = type (string|vector), length, data; heap file marker adds a byte offset so direct
  access is direct (p17-18). index file: table file of links|key|data records; duplicate keys allowed, relative
  record number among equal keys; hashed, no key ordering (B-trees rejected) (p18-20). Index buffer :record_key,
  :set_record_key; index file marker :key, :set_key (descriptions printed swapped) (p19).

## Object storage (p20-28)
- instance file: one per permanent class; fixed-length instance records in a table file ("table instance file");
  heap instance files avoided (p20-21). Conversion operations must be defined per class or store/restore errors.
- record pointer: object holding file and file marker (p21, Fig.4.1).
- as_permanent_object: :store (instance) and :restore (class) bodies printed (p22) -- reimplementable; requires
  per-class :decode (object->record) and :encode (record->object) [naming as printed], :instance_file, record
  pointer :file/:file_marker, instance file :object_class.
- directory_file: index file name -> record pointer: :bind, :find, :replace, :rename (p23); directory file tree
  with pathnames "dir1>dir2>name" (p24-25, Fig.4.4); each volume has a root directory file given at mount (p25).
- directory system (supervisor): system root directory and a process root directory per process; ">dir1>dir2>name"
  vs "dir1>dir2>name"; :bind(Object,Pathname), :retrieve(#as_global_object,Object,Pathname) (p26).
- :link(Volume,">disk1>volume1") inserts a volume root directory file into the directory system; then
  :retrieve(Object,">disk1>volume1>dir1>filename1") (p27).
- permanent directory: directory backed by a directory file; first retrieval restores and inserts the object,
  avoiding file access and duplicate objects; sub-directory files yield permanent sub-directories (p27-28, Fig.4.5).

## File manager process structure (p28-32) -- protocol topology given, message formats not
- File system runs under a process, the file manager, dispatching i/o requests from customers to device handlers
  and replies back (p28).
- Customer interface: manager channel created and kept in a class slot when the file manager is instantiated; a
  file inherits class io_port (a special port), connected to the manager channel at instantiation; file operations
  assemble a request message and wait for a reply (p29, Fig.5.1).
- Device interface: each device handler is an interrupt process (dispatched by hardware on interrupt; a message to
  a channel it waits on raises a trap; it releases the processor when done), with a handler channel; a volume
  object is a device port connected to a handler channel (p30-31, Fig.5.2).
- Manager loop: receive from manager channel or a volume; request -> physical i/o on the volume; completion ->
  post reply to the customer; many customers, unlimited files each, one handler per physical disk (p31, Fig.5.3).
- Boot: "A device handler is instantiated and activated during a system boot-up procedure" (p30); "A file manager
  is instantiated (created) and activated during a system boot-up procedure" (p32).
- Not included: floppy disk files ("only limited part of the facilities"), system boot-up disk: "A system disk has a
  boot-up region that stores CSP (Console Processor of PSI ...) programs, PSI firmware programs, IPL (Initial Program
  Loader), and so on. CSP reads in these programs during system boot-up. The file system supports access to this
  region" (p32-33). Future: file class coercion, file manipulator (window utility), binder (p33).
