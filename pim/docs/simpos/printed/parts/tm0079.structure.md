# TM-079 — 「逐次型推論マシンのOS」 (服部 隆; Nov 1984; HANDWRITTEN manuscript, 18 PDF pp)

All 18 pages were read by eye from 300 dpi renders. OCR is unusable on this manuscript. Listings: `tm0079_p04.txt` (SIMPOS tree), `tm0079_p06.txt` (two inheritance figures), `tm0079_p07.txt` (ESP syntax and the five parts). All renderings of the Japanese below are TRANSLATION.

Section numbering is inconsistent as written. On p5 the ESP chapter is "3.", while p7 has "2.2" and the kernel section on p9 is "3.1".

## Printed in enough detail to reimplement
Only the language-level material qualifies:
- **ESP syntax** (p7). It is the same template as TM-065, with 継承定義 where TM-065 says nature.
- **The five parts** (p8). Clauses end with `;` instead of `.`. Object-oriented calls are written `:述語名(オブジェクト{,パラメタ})`.
- **Inheritance**. Clauses are OR-combined in the listed order, and the list includes the class itself.
- **Demons** are AND-combined before or after the body predicate (p7).

## Sketched only (prose; no interfaces)
- **SIMPOS tree** (p4). The supervisor adds 時計 (clock) and the kernel adds IPL.
- **Kernel** (p9–10):
  - processor management;
  - memory management, including GC, mostly supported in firmware;
  - device management;
  - IPL, which bootstraps SIMPOS.
- **Supervisor** (p10–11):
  - process: a program is an instance of a program class, and its main goal is an instance predicate;
  - pool: referenced by position or key, with a tap for sequential reference;
  - stream: receive blocks when the stream is empty;
  - channel: message communication over streams;
  - port: a two-way message box built on channels;
  - world: a series of directories that gives the default name space;
  - universe: the single system-wide directory tree, shared by all processes;
  - directory: objects are named by a path from the root.
- **I/O media** (p11–13):
  - Window: rectangles that may overlap and contain subwindows; a basic window class plus auxiliary classes inherited selectively; temporary and menu windows; a window manipulator.
  - File: binary, fixed-length-record (table) and variable-length-record (tape) files with direct or sequential access; hash-index files; instance files that store objects as instance records; directory files that name instance records. The VTOC is itself an instance file, and the directory file is part of the supervisor's directory tree. Planned: a file manipulator, a binder and remote file access.
  - Network, at three levels: inter-machine (classes ノード/ソケット/プラグ/ケーブル, i.e. node/socket/plug/cable); inter-process (supervisor channels extended to the network); and remote objects (proxies; inter-process communication is in fact implemented by remote channels). A network manipulator is planned.
- **Programming system** (p14–17):
  - experts, each with an e_window;
  - the coordinator: a background process with no top-level command interpreter. It creates and deletes experts, sends key commands, handles special commands, and offers e_ports (pre-agreed) and a whiteboard (ad hoc) for communication between experts;
  - the debugger/interpreter: DEC-10 Prolog style with a procedure/clause box model, so it can tell whether a failure was in the head or the body. Compiled and interpretive code call each other, and tracing resumes when compiled code calls interpretive code;
  - the editor: a general structure editor using an operator-precedence grammar with user-defined brackets. Tokens are atom, prefix/infix/postfix operator and left/right bracket. ESP needs 2–3 precedence levels (logical `:-` `,` `;`; functional `+ - * /`; predicate `< > =`). The parser and pretty-printer are a separate transducer;
  - the library: class source file (exactly one class), class template (all information except what is inherited; interpretive code, plus compiled code on request), and class object (built from templates along inheritance; an executable image). It also manages predicates. The librarian is planned.
- **Status** (p18, as of Oct 1984). The OS is nearly running. A demo is planned at FGCS'84. The team is about 40 people from ICOT and 5 makers. Release 1 is due at the end of FY1984.
