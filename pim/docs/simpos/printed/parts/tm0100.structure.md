# TM-100 (Hattori, Yoshida, Fujisaki, Feb 1985) -- "Constructing the SIMPOS Supervisor in an Object-oriented Approach"
19 PDF pages. Eyed at 300 dpi: PDF 4, 5, 7-18. Read from OCR only: 1-3, 6, 19 (prose, references).
The paper says of its code: "Although we give several ESP codes as examples, they are not complete." (PDF p7)

## Layers (PDF p4-5, Figure 2.1)
Programming system (Coordinator; Editor, Interpreter/Debugger, Librarian) over Operating system,
which is "further divided into three layers: the i/o medium systems, the supervisor, and the kernel."
I/O medium systems: Window, Network, File, Printer. Supervisor: Process, Pool, Stream, World, Timer.
Kernel: Processor, Memory, Device. Then Hardware. (listings/tm0100_p05.txt)

## Object model (PDF p3-4)
Objects = slots + clauses; classes; multiple inheritance by 'is_a'; clauses of the same operation are
OR'ed in nature order; slots are put together; before/after demons AND'ed with the primary predicate.
ESP class syntax: nature / class slots+clauses / instance slots+clauses / local (listings/tm0100_p04.esp).

## Process model -- PRINTED IN ENOUGH DETAIL TO REIMPLEMENT (core)
- States (PDF p5): running, ready, suspended, dormant. Slot comment adds nil(=dead), "(active) and some others" (PDF p8).
- Operations (PDF p5): :activate(Process, Program), :suspend(Process, Reason), :resume(Process, Reason), :terminate(Process).
- Suspend reasons: a list plus a fast path for stream waits (suspend_reason := Stream). Process becomes ready
  only when suspend_reason==nil and suspend_flag==nil (PDF p9-10). Every state change is bracketed by
  :inhibit_interrupt(#process) / :allow_interrupt(#process); mask nesting is counted in mask_count (PDF p8).
- Creation (PDF p8): class :create allocates a hardware context (":create(#context, Context_number, Stack_number, Context)";
  "If hardware processes are exhausted, then fail"); instance_array maps context_number -> process;
  new process inherits world and user from the creating process, priority 0, sub_priority 0, status dormant.
- Activation (PDF p8-9): status check, :entry_of_invoke(Program, Entry), :set_entry_point(context, Entry),
  :activate(context), :set_priority(context, 0), :clear_masks, status := ready, add to #process!ready_queue.
- Priority: "Corresponds to interrupt level" (PDF p8). Scheduling policy itself is NOT printed: ready queue is a
  with_link chain; how the processor picks from it is not shown.
- Programs (PDF p6, p10-11): a program is an instance of a class inheriting as_program; per-process invocation
  stack; :invoke = :assign, :goal, :resign; empty stack => process dies (:die). Full as_program printed.
- Interrupt processes (PDF p6, p12-13): trap handlers, device handlers, the garbage collector are interrupt
  processes "not dispatched by the supervisor, but by the hardware on an interrupt or a trap". interrupt_process
  overrides :resume/:suspend; the trap/release/allocate steps are ELIDED ("...") in the print -- SKETCHED.
- Boot process (PDF p6, p13): created and activated by the hardware at bootstrap; sole instance of boot_process
  (inherits process, overrides :create and :activate); runs a boot program inheriting as_boot_program; afterwards
  "acts exactly as an ordinary process". No code -- SKETCHED.

## Streams / channels / ports / bounded channels -- PRINTED (near complete)
- stream (PDF p6, p14-15): FIFO pipe of any objects; :put/:get; get on empty suspends the caller with reason
  stream(Stream) after hooking it on waiting_queue; put unhooks one waiter and resumes it. Two queues held as SLOTS
  (not inherited) -- reasons given p14.
- channel (PDF p7, p15): :send(Channel, Message, Sender) / :receive(Channel, Message, Sender); messages carry their
  sender; post_queue slot overridden with post_queue_for_message.
- port (PDF p7, p16): channel + out_port list; send fans out copies of the message to all connected ports via a
  "tap" over the list; :connect/:disconnect named but not printed.
- bounded_channel / bounded_post_queue (PDF p16-18): post queue guarded by a counting semaphore via before/after
  demons on :add_object/:remove_object.
- Not printed: post_queue, waiting_queue, waiting_frame, with_link, semaphore, message bodies (described only).

## Supervisor parts named but not described here
Pool, World, Timer (Figure 2.1). 'world' and 'user' are process slots (PDF p8). "priority control" stream
variation (PDF p7) mentioned only.

## History / performance (PDF p18) -- facts, not design
Design began fall 1982; class specification done end FY1983; first PSI Dec 1983, to software group Mar 1984;
single-process env Apr 1984; "In May, the IPL became operational, so as to allow linking programs directly on PSI";
multi-process env Jun 1984. Process switch reduced from ~20 ms to 2 ms; character input 30 ms after
firmware took over object-oriented calls and slot access.
