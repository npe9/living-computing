# TM-009 Basic Constructs of the SIM Operating System (Hattori, Yokoi; June 1983). 9 PDF pages, OCR read in full; notation fragments eyed (listings/TM-009_p03-07.txt). Earliest SIMPOS design note; written before ESP existed.

- Objects (p3): elementary (atoms, integers, reals), compound `<class-name>(<subobject1>,...)`, variable objects (unification and destructive assignment). The universe = all objects. Clauses are meta-objects of class ':-'.
- Classes (p4-5): multiple inheritance "as found in the Flavor system"; inherited classes are called component classes; instance template definition `new(<class-name>:class, <subobject-names>, <component-class-names>, <required-subobject-names>, <required-component-class-names>)`; required names "must be defined elsewhere" (cf. later ESP required slots/methods: INFERENCE). Relations with typed arguments `<var>:<class>`.
- Pools (insert/extract/find), tap (sequential access to a pool), streams (put/get; get suspends) (p5-6).
- Worlds (p6): scope of knowledge for solving a question; built dynamically from pools; combined world can include other worlds (hypothetical worlds); world is an instance of class 'world' with a pool list searched in order. (Later reports: world = sequence of directories.)
- Processes (p6-8): active entity solving a question in a world; suspends when it finds a non-last answer and may later retry or terminate. Creation by fork `p1::q1 !! p2::q2` (parent waits, join) and remote call `question @ world` (implicit surrogate process; caller suspended; backtrackable). Streams are the only basic IPC. Operations: initialization, termination, suspension, resumption.
- Ports/channels (p8): channel = two connected ports; one-to-many; source/sink port into the outer world via a pseudo-process; "io subsystems ... take care of the actual io operations".
- p9: specification being written "in a semi-formal notation which looks like a logic programming language"; first SIMPOS version hoped for fall 1984.
All SKETCHED; this design (fork/remote call, pool-list worlds) is superseded in later reports (process/program classes in TM-100; INFERENCE that fork syntax was dropped, since no later report shows it).
