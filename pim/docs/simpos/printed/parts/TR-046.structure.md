## Environment stated (p06)
PSI: up to 16 megawords (80 MB) main memory, 1200x912 (or 1280x864) monochrome bitmap display, mouse, Ethernet.
Development on DEC2060 with ESP cross simulator, ESP cross compiler, KL0 assembler, KL0 compiler (all DEC-10
Prolog), EMACS and Z editor. ESP class mechanism: multiple inheritance, before/after demons (Flavors), class slots
(Smalltalk class variables), "component slot" for part-of hierarchy. ~30 people on SIMPOS (p07).

## Window system (p08-10, p13-15) -- concepts only, no window class code
- Window system restricted to basic dialogue: keyboard/mouse input control, output to windows, window allocation;
  echo done by the process; per-process translation table maps key codes to character codes or commands (p09).
  Screen manipulations move_window, select_window, reshape_window (p09).
- Window hierarchy (superior/inferior, recursive; screen is the most superior window), implemented not by class
  inheritance but by mixins as_superior (slot inferiors) and as_inferior (slot superior); each window manages
  display priorities of its inferiors (p09, p13).
- Five window statuses (p09-10): selected (connected to keyboard; only one), shown (completely displayed; superior
  must be shown), exposed (completely displayed on the superior window, superior not shown), overlapped (partially
  or completely hidden in the superior), deactivated (not managed; dot image kept in bitmap memory).
- Table 2 (PDF 23, eyed): Input Keyboard/Mouse, Output: SELECTED done/done/done; SHOWN waiting/done/done;
  EXPOSED waiting (both)/done; OVERLAPPED waiting (both)/waiting/done; DEACTIVATED not available.
- Figure 1 (PDF 25, OCR): example A selected; B shown, B1 shown, B2 overlapped; C overlapped, C1 exposed,
  C2 overlapped.
- Mouse: relative movement; window system computes position, checks the mouse-owning window, uses that window's
  cursor pattern; clicks go to the shown window only; default meaning when outside shown windows (p10, p14).
- Menu window appears at mouse position, sized by item count and longest item; defined by inheriting the menu
  classes and supplying items; Figure 3 system_menu code (p14-15, PDF 27).
- Window program ~100,000 characters; Coordinator ~20,000 characters (p17).

## Coordinator and dialogue levels (p11-16)
- Single-keystroke / mouse-click / menu command language; window = dialogue context (per-window key assignment)
  (p10-11).
- Expert level vs system level; system-level commands go to the Coordinator, expert-level to the expert (p11).
- Translation table: a class instance in a slot of e_window; default_translation_table is the standard; user tables
  inherit it and override keys (p14). :look_up(Table, Window, KeyCode, Destination, Command, HelpString); fourth
  argument [sic -- it is the sixth] a string used by the HELP program; executed by the window manager (p16).
- Coordinator implementation items: expert registration (name + body program), representation, creation/
  selection/deletion, keystroke/mouse processing, program communication; classes e_program, e_process;
  e_process_pool manages experts and handles broadcast; details deferred to [Kurokawa 84] = TR-061 (p15).
- Whiteboard = circular stack of expert messages; user-directed inter-expert transfer (p16).
- Future: advanced HELP, undo/redo, session management (p17-19).

control-m memorize, control-b broadcast {broadcast,_,Program_name,Command}, control-v remember, control-s
