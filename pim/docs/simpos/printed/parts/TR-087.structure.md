# TR-087 Sequential Inference Machine: SIM -- Its Programming and Operating System (Yokoi, Uchida, ICOT Third Laboratory; Oct 1984). 13 PDF pages, OCR read in full. No listing, no figure with code.

Largely the same text as TR-057 with these additions:

## ESP implementation (p3)
- All OO features implemented with KL0 features; OO calls compiled into calls to a runtime subroutine; "three to four times slower than usual predicate calls of KL0"; firmware support planned.

## Supervisor/OS (p4-5)
- Same pool/directory/stream/channel/port/process text; port "being connected to another port with channels". Execution environment = program, library, world, universe (Watanabe et al. 1984). Files "reside in a disk volume and consist of dispersed disk pages" (p5). Remote object operation to make SIMPOS a network OS (p5).
- Window: mouse click sent either to the selected window or the background window, according to mouse position (p5).

## Editor (p8)
- Two-level grammar: tokens by regular expressions/automata, then operator-precedence parse. Parser and pretty printer = "the transducer"; Edips = editor kernel + transducer.

## Exception handling and help (p9-10) -- not in TR-057
- Detector/handler scheme. Two basic classes: event (name of the exception) and situation (context). event subclasses error (warning, fatal error, normal error) and help (help in general, keyboard help). Situation is stack-like: each program sets handlers for its process and deletes them on normal end; several handlers may apply to one event: situation sorts them and applies them "in the mode of non-determinism". Catch/throw-style global exit and a common command loop are built on event/situation. SKETCHED: no method names.

## Development and debugging (p10-11)
- Cross tools: ESP interpreter, ESP cross compiler (to KL0), KL0 cross compiler, KL0 cross linkage editor, linkage-database utilities (Prolog, some PASCAL, on a mainframe).
- Runtime support system written directly in KL0: OO calling mechanism; mnemonic tracing (procedure box model; skip, redo); slot inspection; I/O via built-ins read_console / display_console using the console processor (p10-11).
- IPL (p11): "a rather flexible initial program loader was implemented in ESP. Using this IPL, modules of programs to be debugged are separately compiled, partially linked and stored in flexible disks (Ueda et al. 1984). Loading from the flexible disk and the final linkage are done by the IPL on PSI itself." Before that: compile+link on mainframe, transfer to a minicomputer by network, download to PSI. No disk format given. SKETCHED.
- System tracer (p11): ESP program, separate process, traces KL0-level execution of other processes (Sato et al. 1984).

## History (p11-12)
- Design began fall 1982; functional spec end FY1982; ~20-member software group June 1983; class specification completed end FY1983; ESP requirements finalised summer 1983; SIMPOS coded in ESP from class specs, cross-debugged on the ESP simulator from Oct 1983; first PSI Dec 1983; firmware debugging end Feb 1984; operational September (1984); preliminary SIMPOS for internal use October (1984); ~40 people from ICOT, Mitsubishi, NEC, Oki, Matsushita, Sharp.
