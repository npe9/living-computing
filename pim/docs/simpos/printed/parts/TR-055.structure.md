# TR-055 SIMPOS: An Operating System for a Personal Prolog Machine PSI (Hattori, Tsuji, Yokoi; Apr 1984). 23 PDF pages (folio = PDF-3), OCR read in full; p10, p13, p17 checked by eye. No class listing; notation fragments in listings/TR-055_p10.esp.

## Layers (p2, p6-7)
- OS has three layers: hardware resource management (= the kernel: processor management, memory management incl. garbage collection, I/O device management), basic constructs management (= the supervisor: pools and streams, processes and worlds, channels and ports), i/o medium management (file, window, network subsystems).
- Programming system = expert processes: listeners (command interpreters), editors, compilers, debugging interpreters, librarians, analyzers; coordinated by a coordinator expert (p7-8).

## Hardware model as seen by the OS (p4-5)
- 2 Mwords of 40-bit words (32 data + 8 tag); bitmap display, keyboard, mouse; hard disks and floppy disks; LAN interface; "a console microprocessor to support the main processor in initial loading and diagnostics".
- Logical-to-physical address translation, but no virtual address space. 256 areas of 16 Mwords; each area a heap or a stack. A KL0 execution needs four stacks (control, local, global, trail); "Therefore, PSI can have a maximum of 63 contexts executing at the same time" (63 sets of internal process-control registers). "Interrupts and traps cause direct context switching at the hardware level, but process dispatching must be controlled by software." REIMPLEMENTABLE constraint: 4 areas per process.

## Objects (p9-11)
- Object = a KL0 vector, identified by its location (the object pointer), which is constant; slots updated destructively. Instance = template vector {<code>,<attribute1>,...}, <code> = code for instance predicates; slot accessor `X = Point!x`. Operation head/goal form `:<action_name>(<object1>,...)`; dispatch on the class of the first argument. Multiple inheritance; clauses of the class and its superclasses are OR'ed. REIMPLEMENTABLE at representation level (layout order beyond "code first" not given).

## Supervisor constructs (p12-15)
- pool: insert/extract/find. stream: FIFO, put/get, retrieve suspends when empty; "SIMPOS uses streams as the only basic construct for synchronization and communication between processes". tap: stream out of a pool.
- Processes are the only active entities; objects passive. process: suspend/resume/terminate.
- world: scope of global object references = sequence of directories (a directory = pool of name/object associations); many worlds = "sometimes called a universe"; shared worlds see each other's changes. permanent directory = directory backed by a directory file.
- channel on top of streams, message protocol, may cross machines; port: two channels connect two ports; one-to-many connection; i/o port to outer world.
- I/O subsystems each have a main process "manager" with a manager port connected to the user's i/o port; request/reply. A pool can be accessed as if it were an I/O device (p15). SKETCHED (no message formats).

## File subsystem (p16-18)
- Files in a disk volume: binary, table (fixed-length), heap (variable-length, "permanent heap area"). Region = area of a volume storing a file; disk pages allocated as it grows; logical address (region number, offset) translated via a per-region page map. Access modes random (file marker), sequential (file tap holding a marker), indexed (key). Multi-level directory files; pathname ">dir1>dir2>file1" resolved from the root directory file. Instance file = table file of objects; each class knows how to store/restore its instances; VTOC is an instance file of file objects; directory files name instance records too (">dir1>dir2>object"). SKETCHED: the page-map/region scheme is the most concrete part, no layouts.

## Window subsystem (p18-20)
- Windows built on the class system "as the LISP Machine does on its Flavor system"; basic window classes plus feature classes (scrolling, labelling, framing). States: shown (of which one is selected), de-exposed, de-activated (three-plus-selected, vs TR-057's five). Subwindows; temporary windows; menu windows (mouse click shows a temporary menu; moving out cancels). SKETCHED.

## Network (p20-21)
- Three levels: inter-machine (node, socket, cable, plug: create a plug on a socket, connect to another socket, read/write), inter-process (remote channels), remote object operations (operation encoded into a message, decoded remotely; each class knows its encoding). SKETCHED.

## Status (p22): functional design done; coding and debugging in ESP on a development system; first version to be released by end of FY1984.
